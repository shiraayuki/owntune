# M3 v0.5.0 Edit Info Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Edit song fields (one song, or all songs of an album/artist), written into the file tags and the database.

**Architecture:** Rust `write_tags` writes one file atomically via lofty. Dart: `TrackTags` (the eight fields) and `TagEdit` (per-field change for bulk) in `lib/edit/`; `TagSaver` writes each file, then updates all successful rows in one transaction via `TrackRepository.updateTags`. `EditInfoScreen` is opened from the song menu and from a "…" menu on album/artist pages, which follow their songs across a rename.

**Tech Stack:** Rust + lofty 0.25.5 + flutter_rust_bridge 2.13.0; Flutter 3.50, flutter_riverpod 3, drift.

**Spec:** `docs/superpowers/specs/2026-11-19-m3-v0.5.0-edit-info-design.md`

## Global Constraints

- English everywhere; `package:material_ui` / `package:cupertino_ui`; `flutter analyze` → "No issues found!"; `cargo clippy -- -D warnings`, `cargo fmt --check`.
- After changing `rust/src/api/`: `flutter_rust_bridge_codegen generate`; generated code is committed.
- Widget/unit tests never call Rust: the writer function is injected (`tagSaverProvider` overridden in `pumpApp`).
- Write the file first, then the row; a failed write leaves the row unchanged.
- The stored `contentHash` and `fileName` never change on edit.

## Review Focus

1. **Bulk edit with mixed values** — an untouched "Mixed" field keeps each song's own value. Test in Task 2.
2. **Clearing a field** — empty text removes the tag item and sets the column to null (numbers too). Tests in Tasks 1 and 2.
3. **Write failure on one song of a bulk save** — the others are saved, the dialog names the failed one, its row is unchanged. Test in Task 3.
4. **Album renamed from its own page** — the page shows the renamed album instead of closing. Test in Task 5.
5. **Whitespace-only input** — treated like empty (cleared), never stored as "  ". Test in Task 2.

### Task 1: Rust `write_tags`

**Files:** Modify `rust/src/api/library.rs`; regenerate `lib/src/rust/`.

**Interfaces:** Produces
```rust
pub struct TagValues { pub title: Option<String>, pub artist: Option<String>, pub album: Option<String>,
  pub album_artist: Option<String>, pub genre: Option<String>, pub track_number: Option<u32>,
  pub disc_number: Option<u32>, pub year: Option<u32> }
/// Writes `tags` into the file at `path` (None removes the item). Copies to
/// `<stem>.part.<ext>` next to it, writes there, renames over the original.
/// Returns an error message, or None on success. Never panics.
pub fn write_tags(path: String, tags: TagValues) -> Option<String>
```
Dart after codegen: `Future<String?> writeTags({required String path, required TagValues tags})`.
Primary tag of the file (`primary_tag_type()`), inserted when missing; title/artist/album/genre via `Accessor` set/remove; album artist via `insert_text(ItemKey::AlbumArtist, …)` / `remove_key`; year via `set_date(Timestamp { year, ..Default })` / `remove_date()`; save with `save_to_path(part, WriteOptions::default())`, then `fs::rename`.
