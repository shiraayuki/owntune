# v0.4.2 — Shuffle and the Now Playing top row

**Size:** small change. Completes M2 (shuffle was left out of v0.4.0 and v0.4.1).

## Intent

Shuffle should feel like Spotify's: spread out rather than truly random. True randomness often plays three songs by the same artist in a row, which feels *less* random. Plus one visual fix found on the iPhone: Now Playing's top row (down chevron, "…") sits under the status bar and the Dynamic Island.

## Goals

- **Spread shuffle.** Songs by the same artist are spread evenly over the shuffled list, with random offsets so it does not look regular; within one artist, songs of the same album are spread too (the approach Spotify described for its shuffle). Artist and album as the library shows them (album artist falls back to artist, as in `Library.from`).
- **Sticky toggle** in Now Playing (Spotify): shuffle stays on until it is turned off, also across new queues.
  - Turning it on keeps the current song playing and makes every other song of the queue (also those already played) the upcoming list in spread order, as Spotify shuffles the whole list; the current song becomes the first entry, so Previous restarts it. The original order is kept aside.
  - Turning it off continues in the original order from the current song: the songs before it in the original order become the history again (Previous works), those after it become upcoming.
  - Songs added with Play Next / Play Later while shuffle is on are placed as now (right after the current song / at the end) and are not shuffled; they are also added to the original order (Play Next right after the current song, Play Later at the end), so turning shuffle off keeps them.
  - Reordering or removing in Up Next while shuffled changes only the shuffled order; a removed song also leaves the original order. Clearing Up Next clears the upcoming songs of both orders.
- **Tapping a song** in a list while shuffle is on plays that song first and shuffles the rest of the list.
- **Album and artist pages:** "Shuffle" turns shuffle on and starts the list with a random song (chosen by the same spread order). "Play" turns shuffle off and plays from the start.
- **Repeat all with shuffle:** when the list wraps around, it is shuffled again; the song that just ended is not played first again (when the list has more than one song).
- **Restart:** the shuffle flag and the original order are saved with the player state and restored. An older saved state without them restores with shuffle off.
- **Deleted songs** leave both orders.
- **Now Playing top row** sits below the status bar / Dynamic Island; the blurred backdrop still reaches the top edge.

## Non-goals

- A shuffle button on the lock screen or in the Android notification (iOS shows none there; system Next/Previous follow the shuffled order anyway).
- Spotify's "Smart Shuffle" (mixing in recommendations) — offline, there is nothing to recommend from.
- Avoiding recently played songs across sessions, weighting by play count.

## Anti-goals

- Shuffle that changes behaviour of the existing features with shuffle off (queue, Up Next, repeat, restore must behave exactly as in v0.4.1).
- Visibly regular patterns (e.g. strict artist rotation A, B, C, A, B, C).

## Approaches

1. **Reorder the queue itself, keep the original order aside** (picked). The queue's entries are the play order; `PlayQueue` additionally holds the original order (entry keys) while shuffle is on. Up Next, Previous, system controls and restore keep working unchanged because they already follow the entries.
2. **Keep entries in original order, add a separate play-order permutation.** Every reader of the queue (Up Next, next/previous, system controls, snapshot) would have to map through the permutation; more code and more places to get wrong, no benefit for the user.

## Decided

- Approach 1.
- Shuffle is a property of the queue state (like repeat) and survives `playList` (a new queue started while shuffle is on is shuffled).
- The randomness source is injectable so tests are deterministic.
- Top-row fix: Flutter's modal bottom sheet removes the top padding (`MediaQuery.removePadding(removeTop: true)` when `useSafeArea` is false), so `viewPaddingOf(context).top` is 0 inside the sheet. `showPlayer` reads the top inset from the context it opens from and passes it to `PlayerSheet`.
- Version `0.4.2`; CLAUDE.md status updated (M2 complete).

## Left to the builder

The exact spread algorithm (within the rules above), the `PlayQueue` API, the snapshot JSON keys, how the shuffle button shows its "on" state (accent colour like repeat), test split. Tests: unit tests for the spread (no same-artist neighbours when avoidable, every song exactly once, current song first/kept), toggle on/off round-trip, Play Next/Later and Up Next edits while shuffled, repeat-all reshuffle, snapshot round-trip and old snapshots; widget tests for the three buttons and the top inset.
