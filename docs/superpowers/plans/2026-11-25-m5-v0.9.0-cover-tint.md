# Now Playing Tinted by the Cover Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** In dark mode the full-screen player takes its background tint and its accent (play button, liked heart, active toggles, Up Next) from the current cover.

**Architecture:** A pure function turns 64×64 RGBA pixels into `CoverColors`; a cached `FutureProvider.family` decodes each cover once in an isolate. The player sheet replaces `OwntuneColors.accent`/`accentText` inside its own subtree with an `AnimatedTheme`, so every existing accent use in the player follows without touching each widget, and paints a veil in `background` over the blurred cover.

**Tech Stack:** Flutter, Riverpod 3, `image` 4 (already a dependency), `Isolate.run`.

**Spec:** `docs/superpowers/specs/2026-11-25-m5-v0.9.0-cover-tint-design.md`

## Global Constraints

- Only the full-screen player is tinted; the mini player keeps the accent.
- Light mode ("Paper") stays untinted. No cover, an unreadable cover, or colours not computed yet: the accent, as today.
- White text on `background` ≥ 4.5:1; `onButton` on `button` ≥ 4.5:1 (WCAG contrast ratio).
- Colours fade over 400 ms on a song change.
- No database change; colours are cached for the session only.
- Imports: `package:material_ui/material_ui.dart`, `package:cupertino_ui/cupertino_ui.dart`; `flutter analyze` must report "No issues found!".

## Review Focus

- An unreadable or missing cover file: the player shows the accent and never throws (Task 1 garbage-bytes test, Task 2 missing-file test).
- A PNG cover with transparent areas: transparent pixels do not count (Task 1 transparency test).
- Swiping quickly through songs: the tint follows the current song, never a stale one (Task 2 song-change test).
- Switching to light mode while the player is open: the accent comes back (Task 2 light-mode test).
- A large imported cover (2000 px and more): decoding happens off the UI isolate (Task 2: provider uses `Isolate.run`).

### Task 1: Colours from cover pixels

**Files:**
- Create: `lib/player/cover_colors.dart`
- Test: `test/player/cover_colors_test.dart`

**Interfaces:**
- Produces:
  - `class CoverColors { const CoverColors({required Color background, required Color button, required Color onButton}); }` with `==`/`hashCode`.
  - `CoverColors? coverColorsFromPixels(Uint8List rgba, int width, int height)` — null when no pixel has alpha ≥ 128.
  - `CoverColors? coverColorsFromImage(Uint8List encoded)` — top-level (for `Isolate.run`): `img.decodeImage`, `img.copyResize` to 64×64, RGBA bytes into `coverColorsFromPixels`; null when the bytes do not decode.
  - `double contrastRatio(Color a, Color b)` — WCAG 2 contrast ratio.

- [x] **Step 1: Write the failing tests** (helper `solid(r, g, b, {a = 255})` builds a 64×64 RGBA buffer)
  - `orange cover`: `coverColorsFromPixels(solid(255, 122, 0), 64, 64)`; expect `HSLColor.fromColor(background).hue` in 15..45, `button` hue in 15..45, `contrastRatio(white, background) >= 4.5`, `contrastRatio(onButton, button) >= 4.5`, `HSLColor(button).lightness > HSLColor(background).lightness`.
  - `near-white and near-black covers keep the contrast`: for `solid(250, 250, 245)` and `solid(5, 5, 8)` the two contrast assertions hold.
  - `grey cover gives neutral colours`: `solid(128, 128, 128)` → `HSLColor(background).saturation < 0.1`.
  - `a vivid colour beats a larger grey area`: 70 % pixels (128,128,128), 30 % (30, 90, 230) → background hue in 205..235.
  - `transparent pixels do not count`: half the pixels (255, 0, 0, a: 0), half (255, 122, 0) → hue in 15..45; all transparent → null.
  - `encoded images`: `coverColorsFromImage(img.encodePng(<solid orange 200×200 image>))` is not null with hue in 15..45; `coverColorsFromImage(Uint8List.fromList([1, 2, 3]))` is null.
- [x] **Step 2: Run** `flutter test test/player/cover_colors_test.dart` — Expected: FAIL (file/functions missing).
- [x] **Step 3: Implement** in `lib/player/cover_colors.dart`. Algorithm (pinned): bucket opaque pixels by 4 bits per channel; a bucket's colour is the mean of its pixels; a bucket is vivid when its HSL saturation ≥ 0.25 and lightness in 0.12..0.88; pick the vivid bucket with the highest `count * (0.5 + saturation)` if it holds ≥ 5 % of the opaque pixels, else the most frequent bucket. `background`: that hue and saturation, lightness = min(lightness, 0.35), then lowered in 0.02 steps until white reaches 4.5:1. `button`: same hue, saturation min(s, 0.7), lightness 0.78, raised in 0.02 steps until `onButton` reaches 4.5:1. `onButton = Color(0xff16120f)`.
- [x] **Step 4: Run** `flutter test test/player/cover_colors_test.dart` — Expected: PASS; `flutter analyze` — "No issues found!".

### Task 2: Tinted player sheet

**Files:**
- Create: `lib/player/cover_tint.dart` (provider)
- Modify: `lib/player/player_sheet.dart` (`_PlayerSheetState.build`, backdrop stack)
- Test: `test/player/player_sheet_test.dart` (new group `cover tint`)

**Interfaces:**
- Consumes: Task 1 `CoverColors`, `coverColorsFromImage`.
- Produces: `final coverColorsProvider = FutureProvider.family<CoverColors?, String>(...)` keyed by the cover file name; reads `ref.watch(storageProvider).coverFile(name)`, `Isolate.run(() => coverColorsFromImage(bytes))`; any error (missing file, decode) → `null`. Not auto-dispose (session cache).

- [x] **Step 1: Write the failing widget tests** (override `coverColorsProvider` with `const tint = CoverColors(background: Color(0xff5a1e00), button: Color(0xffffd9b8), onButton: Color(0xff16120f))` for any key; songs with `coverFile: 'c.jpg'`; dark mode via the settings override the other tests use)
  - `dark mode with a cover tints play button and liked heart`: the `player-play` IconButton's style background resolves to `tint.button`, its icon colour to `tint.onButton`; a liked song's heart (`player-like`) icon colour is `tint.button`.
  - `active repeat uses the tint`: after one tap on `player-repeat` its icon colour is `tint.button`.
  - `light mode keeps the accent`: same song in light mode → play button background is the theme's `accent`.
  - `a song without a cover keeps the accent`: `coverFile: null` → `accent`.
  - `colours not ready keep the accent`: provider override that never completes → `accent`.
  - `the tint follows a song change`: two songs with different covers mapped to different `CoverColors`; after `next`, pump 500 ms → play button background is the second song's `button`.
  - `a missing cover file gives no tint`: real `coverColorsProvider` with `LibraryStorage` pointing to a temp dir without the file → resolves to `null` (provider-level test with a `ProviderContainer`).

- [x] **Step 3: Implement.** In `_PlayerSheetState.build`: `tint = dark && cover != null ? ref.watch(coverColorsProvider(cover)).value : null`; also `ref.watch` the provider for the next entry's cover (`queue.nextIndex(auto: true)` → track → `coverFile`) to warm it, ignoring the value. Wrap the sheet's `ClipRect` child in `AnimatedTheme(duration: const Duration(milliseconds: 400), data: tint == null ? theme : theme.copyWith(extensions: [c.copyWith(accent: tint.button, accentText: tint.onButton)]), …)`. Between the blurred cover and the existing bottom gradient add a veil: a vertical gradient from `tint.background` at alpha 0.85 (top) to `tint.background` at alpha 0 at 0.75, animated with `TweenAnimationBuilder<Color?>` (400 ms); no veil without a tint.
