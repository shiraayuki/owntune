# M0: Skeleton – Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

> **Status:** Completed on 2026-11-18 (release `v0.1.0`). Deviations made during execution are noted inline as *Executed:*.

**Goal:** Empty Flutter app `owntune` with a Rust core (`lofty`) that runs on Linux, is built in CI as an APK and an unsigned `.ipa`, and starts on the iPhone via sideloading.

**Architecture:** Flutter project with the platforms iOS/Android/Linux. Rust crate in `rust/`, bound via flutter_rust_bridge v2 (`integrate`, built by cargokit during the normal `flutter build`). A home screen shows the result of a Rust call or, if the Rust core fails to load, the error message. Two GitHub Actions workflows: Linux (checks + APK) and macOS (`.ipa`).

**Tech Stack:** Flutter (stable), Dart, Rust (stable, rustup), flutter_rust_bridge v2, lofty, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-18-m0-skeleton-design.md`

## Global Constraints

- Platforms: iOS, Android, Linux. No others (`--platforms ios,android,linux`).
- Bundle ID / application ID: `dev.owntune.app` (iOS `PRODUCT_BUNDLE_IDENTIFIER`, Android `applicationId`, Linux `APPLICATION_ID`).
- Rust crate lives in `rust/`; generated flutter_rust_bridge code is committed.
- `flutter_rust_bridge` (Dart package), `flutter_rust_bridge` (Rust crate), and `flutter_rust_bridge_codegen` have **exactly the same version**, pinned (no `^`).
- The Flutter version in CI is pinned and equal to the locally installed one.
- No packages from later milestones (no drift, Riverpod, just_audio, file_picker).
- Repo: public, `owntune`, main branch `main`.
- No local Android SDK; Android is only built in CI.

## Review Focus

1. **Rust library does not load on the iPhone** (missing framework, wrong architecture, hash mismatch) → the app must not crash with a white screen but show the error message; without a Mac this is the only diagnosis. Test: Task 4, `loadCoreStatus` with a throwing `init`.
2. **Rust API changed, codegen forgotten** → CI fails instead of building stale code. Test: Task 5, codegen check step.
3. **Versions of FRB Dart package, crate, and codegen drift apart** → runtime error in `RustLib.init`. Test: Task 3, "check versions" step.
4. **`.ipa` contains a simulator build or no Rust code** → CI green, app broken on the device. Test: Task 6, check artifact contents.
5. **Fresh checkout does not build** (locally generated files not committed, `rust/target` committed by accident) → CI builds from a clean checkout; Task 3 checks `git status` for `target/`.
