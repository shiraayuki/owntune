# M2 v0.4.0 Player Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Play the library inside the app: tap-to-play with the list as the queue, mini player, full-screen Now Playing, Up Next, Play Next/Later, repeat.

**Architecture:** A pure `PlayQueue` value type holds entries, current index, source label and repeat mode. A Riverpod `PlayerController` owns the queue and drives an `AudioEngine` interface (one file at a time); `JustAudioEngine` implements it with just_audio (media_kit on Linux), widget and unit tests use `FakeAudioEngine`. The controller stores track ids and follows `tracksProvider`, so deletions and imports keep the queue in sync.

**Tech Stack:** Flutter 3.50, flutter_riverpod 3 (no codegen), just_audio 0.10.6, just_audio_media_kit 2.1.0 + media_kit_libs_linux 1.2.1, audio_session 0.2.4, drift.

**Spec:** `docs/superpowers/specs/2026-11-19-m2-v0.4.0-player-design.md`

## Global Constraints

- Everything in the repo in English (code, comments, tests, docs, commits, UI strings).
- Import `package:material_ui/material_ui.dart` and `package:cupertino_ui/cupertino_ui.dart`, never `package:flutter/material.dart` / `cupertino.dart`. `flutter analyze` must report "No issues found!".
- No shuffle logic. Shuffle controls render **disabled** (`onPressed: null`).
- No background mode, no `UIBackgroundModes`, no audio_service, no restore after restart.
- Tracks play from `LibraryStorage.audioFile(track.fileName)`; never store paths.
- Startup errors become `StartupFailed`; playback errors become a visible notice `Couldn't play “<title>”` (title via `displayTitle(track.title, track.originalName)`).
- Unit/widget tests never construct `JustAudioEngine`; `pumpApp` overrides `audioEngineProvider` with `FakeAudioEngine`.
- just_audio gotcha: `AudioPlayer.play()` completes only when playback stops — never `await` it.
- Mockup values: mini player 60pt high, 16pt radius, 8pt side inset, 44pt art (8pt radius), 2pt accent progress line inset 14pt; now-playing title tinted with `OwntuneColors.accent`.

## Review Focus

1. **Import while playing** — a new `tracksProvider` snapshot must not reload or restart the current song. Test in Task 3.
2. **Rapid taps** — tapping song A then B before A has loaded must end with B playing; A's late load must not start. Test in Task 3.
3. **Zero or unknown duration** (`durationMs: 0`) — progress line and scrubber clamp to 0..1, no NaN/exception. Test in Task 6.
4. **Queue emptied while the player is open** (current and only song deleted) — the player sheet closes and the mini player disappears. Test in Task 7.
5. **Removing / reordering by entry after the queue changed underneath** (a song deleted between build and swipe) — acts on the right entry key, never on a shifted index. Test in Task 3.

### Task 2: PlayQueue model

**Files:**
- Create: `lib/player/play_queue.dart`
- Test: `test/player/play_queue_test.dart`

**Interfaces:**
- Produces:
  ```dart
  enum RepeatMode { off, all, one }   // RepeatMode.next: off→all→one→off
  class QueueEntry { const QueueEntry(this.key, this.trackId); final int key; final int trackId; }
  class PlayQueue {
    const PlayQueue({this.entries = const [], this.index = 0, this.source, this.repeat = RepeatMode.off});
    static const empty = PlayQueue();
    factory PlayQueue.of(List<int> trackIds, {required int start, String? source, RepeatMode repeat});
    final List<QueueEntry> entries; final int index; final String? source; final RepeatMode repeat;
    bool get isEmpty; QueueEntry? get current; List<QueueEntry> get upcoming;  // entries after index
    bool get hasNext;                      // false only on the last entry with repeat off
    int? nextIndex({required bool auto}); // auto=true: song ended (repeat one → index); null = stop
    int? get previousIndex;                // null on the first entry (caller restarts)
    PlayQueue withRepeat(RepeatMode r);
    PlayQueue jumpTo(int key);
    PlayQueue insertNext(int trackId); PlayQueue append(int trackId);
    PlayQueue moveUpcoming(int from, int to); // indices within [upcoming], ReorderableListView semantics (to is pre-removal)
    PlayQueue remove(int key); PlayQueue clearUpcoming();
    /// Drops entries whose track id is not in [existing]. If the current entry goes, index points at the entry that followed it, or at the last remaining entry when none followed; `currentRemoved` is then true.
    ({PlayQueue queue, bool currentRemoved}) retain(Set<int> existing);
  }
  ```
- Entry keys are unique within a queue and never reused (keep a private counter: `max key + 1`).

- [ ] **Step 1: Write failing tests** in `test/player/play_queue_test.dart`:
  - `of starts at the tapped song` — `PlayQueue.of([1,2,3], start: 1).current!.trackId == 2`, `upcoming` ids `[3]`.
  - `nextIndex wraps only with repeat all` — on last entry: off → `null`, all → `0`; `hasNext` false only for off.
  - `repeat one repeats only when the song ends` — repeat one, index 0 of 3: `nextIndex(auto: true) == 0`, `nextIndex(auto: false) == 1`.
  - `RepeatMode cycles off, all, one`.
  - `previousIndex is null on the first entry`.
  - `insertNext puts the song right after the current one`; `append adds it at the end`; both on `PlayQueue.empty` give a one-entry queue with index 0.
  - `duplicates get distinct keys` — `append(2)` on a queue already holding 2 → two entries with trackId 2 and different keys.
  - `moveUpcoming reorders only upcoming entries` — `[1,2,3,4]` index 0, `moveUpcoming(0, 3)` → ids `[1,3,4,2]`.
  - `remove and clearUpcoming keep the current song` — `clearUpcoming` on index 1 of 4 → ids `[1,2]`, index 1.
  - `retain keeps the current song when others go` — `[1,2,3]` index 1, `retain({1,2})` → ids `[1,2]`, index 1, `currentRemoved == false`.
  - `retain moves to the following song when the current one goes` — `[1,2,3]` index 1, `retain({1,3})` → current trackId 3, `currentRemoved == true`.
  - `retain falls back to the last remaining song when none follows` — `[1,2,3]` index 2, `retain({1,2})` → current trackId 2, `currentRemoved == true` (the controller loads it paused at 0, like the end of the queue).
  - `retain of nothing empties the queue` — `retain({})` → `isEmpty`.
  - `remove by key after a retain hits the right entry` (Review Focus 5) — `[1,2,3,4]`, take key of trackId 4, `retain({1,2,4})`, `remove(key)` → ids `[1,2]`.

- Produces:
  ```dart
  class PlayerState {
    const PlayerState({this.queue = PlayQueue.empty, this.playing = false});
    final PlayQueue queue; final bool playing;
  }
  final playerProvider = NotifierProvider<PlayerController, PlayerState>(PlayerController.new);
  class PlayerController extends Notifier<PlayerState> {
    Future<void> playList(List<Track> tracks, {required int start, required String source});
    Future<void> togglePlay(); Future<void> next(); Future<void> previous();
    Future<void> seek(Duration position); void cycleRepeat();
    Future<void> playNext(Track t); Future<void> playLater(Track t);
    Future<void> jumpTo(int key); void moveUpcoming(int from, int to);
    Future<void> remove(int key); void clearUpcoming();
    Stream<String> get notices;   // broadcast; "Couldn't play “<title>”"
  }
  final playerPositionProvider = StreamProvider<Duration>(...);   // from the engine
  final currentTrackProvider = Provider<Track?>(...);             // current entry resolved in tracksProvider
  final playerNoticesProvider = StreamProvider<String>(...);
  Future<void> TrackRepository.markPlayed(int id); // playCount + 1, lastPlayedAt = now
  class FakeAudioEngine implements AudioEngine {
    final loaded = <String>[];          // file names (basename) in load order
    bool playing; Duration lastSeek;
    Set<String> failing;                // basenames whose load throws
    Completer<void>? holdLoad;          // when set, load waits on it
    void emitPosition(Duration d); void complete(); void emitError(Object e);
  }
  ```
- Rules implemented here (all from the spec "Playback rules"): previous restarts after 3 s (track the latest position event); next with `hasNext == false` is a no-op; end of queue with repeat off → pause, seek 0, keep loaded; completed → `markPlayed(currentId)` then advance with `nextIndex(auto: true)`; load failure → notice + try the following entry, unload and clear the queue after `entries.length` consecutive failures; `tracksProvider` updates → `retain(ids)`, reload only if `currentRemoved` (keep `playing` when a following entry took over; load paused at 0 when it fell back to the last remaining entry), unload if empty; Play Next/Later on an empty queue starts playing; `playList` always restarts from the given list. Every load bumps a generation counter; a load whose generation is stale after its await does nothing (Review Focus 2).
