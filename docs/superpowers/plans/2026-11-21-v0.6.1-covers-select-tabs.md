# v0.6.1 Covers, Multi-Select and Text Tabs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Text tabs instead of segmented switches, covers (pick/crop/remove, single and bulk) in Edit Info written into the files, multi-select in Songs with bulk Edit Info/Delete, plus the deferred v0.6.0 fixes.

**Architecture:** `TextTabs<T>` replaces `Segmented<T>` in two places. The cover change travels as a `CoverEdit` inside `TagEdit`; `TagSaver` writes file first (Rust `write_tags` gains `remove_cover`), stores a new cover once under its BLAKE3 (new sync Rust `hash_bytes`), then updates tags + `coverFile` of the written rows in one transaction. Picking uses the existing `file_picker` behind a `CoverPicker`; cropping is an own `InteractiveViewer` page whose math and image work are pure Dart functions. Multi-select is a Riverpod notifier read by the shell (title row, bottom bar) and the Songs list.

**Tech Stack:** Flutter 3.50 / Dart 3.14, flutter_riverpod 3, drift, file_picker 13.4, image 4.13, Rust + lofty 0.25.5 via flutter_rust_bridge 2.13.0.

**Spec:** `docs/superpowers/specs/2026-11-21-v0.6.1-covers-select-tabs-design.md` (read it with this plan; mockups: `docs/mockups/switch-v1/b1-*`, `b2-*`, `switch.css`; `docs/mockups/roadmap-v1/01`–`04`, `roadmap.css`).

## Global Constraints

- All code, comments, tests, docs, commit messages and UI strings in English.
- Import `package:material_ui/material_ui.dart` and `package:cupertino_ui/cupertino_ui.dart`, never `flutter/material.dart` / `flutter/cupertino.dart`.
- No new packages.
- `flutter analyze` must report "No issues found!"; `flutter test` green after every task; Rust: `(cd rust && cargo test && cargo clippy -- -D warnings && cargo fmt --check)`.
- After any change in `rust/src/api/`: `flutter_rust_bridge_codegen generate`, commit the generated files.
- DB stores file names only; covers under `covers/<blake3-of-image>.<ext>`, written via `covers/<random>.part`.
- `contentHash` and `fileName` never change on an edit.
- A row's tags/`coverFile` change only if its file was written successfully.
- Covers made from a picked image: JPEG quality 90, side ≤ 1000 px, never upscaled.
- `Segmented` stays only in the Settings sheet.
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

- Bulk cover on an album where one file fails to write: that song keeps its old `coverFile`, the others get the new one, and the old cover file survives while anything still references it.
- Removing the cover in bulk where some songs have none: those songs are skipped (no write, no row change) unless their tags change.
- A picked photo with EXIF rotation (portrait phone photo): the crop page and the result are upright.
- Deleting songs while selected (song menu elsewhere, import rollback): their ids leave the selection, the count drops, actions never touch a deleted id.
- Very wide or tall images (e.g. 4000×500 panorama): the crop starts covering the frame, can never show a gap, and the result is square.

Each of these has a test in the owning task (Tasks 3, 3, 4, 7, 4).

### Task 4: Cover image processing and crop math (pure)

**Interfaces:**
- Produces:

  - `UprightCover? uprightCover(Uint8List source)` — decode with `image` (null if unreadable, incl. HEIC), `bakeOrientation`, downscale so the longer side ≤ 2000 (no upscale), encode JPEG quality 95. Synchronous; callers use `Isolate.run`.
  - `Uint8List cropCover(Uint8List upright, Rect rect)` — decode, `copyCrop` to `rect` (rounded, clamped to the image), resize to ≤ 1000 px side (no upscale), `encodeJpg(quality: 90)`. Synchronous.
  - `Matrix4 initialCropTransform(Size image, double frame)` — child is laid out at `image * (frame / image.shortestSide)`; returns the translation that centers it in the `frame`×`frame` viewport.
  - `Rect cropRectFor(Matrix4 transform, Size image, double frame)` — the viewport square mapped back into image pixels (inverse transform, divided by the base scale `frame / image.shortestSide`), clamped to the image and kept square.
