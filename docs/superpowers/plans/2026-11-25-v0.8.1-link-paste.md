# v0.8.1 Paste a Link Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A YouTube or SoundCloud link pasted (or submitted) in Search Online looks up that one song and opens the Download sheet right away.

**Architecture:**
- A pure `parseOnlineLink` turns the field text into a sealed `OnlineLink`, or null when the text is not a link.
- `OnlineSource.lookup(OnlineLink)` returns one `OnlineResult`:
  - YouTube: from the player response's `videoDetails`.
  - SoundCloud: from `/resolve`.
- `SearchOnlineScreen` detects a link on paste or submit, shows its spinner, then calls `showDownloadSheet`. Errors go to the existing error state.

**Tech Stack:** Flutter 3.50 / Dart 3.14, flutter_riverpod 3, the existing `HttpTransport`/`InnertubeClient`/`SoundcloudClient`, flutter_test.

**Spec:** `docs/superpowers/specs/2026-11-25-v0.8.1-link-paste-design.md` (the authority; read it first).

## Global Constraints

- Imports: `package:material_ui/material_ui.dart` and `package:cupertino_ui/cupertino_ui.dart`. Everything is in English.
- `flutter analyze` reports "No issues found!", `dart format lib test integration_test` changes nothing, and `flutter test` is green.
- No new packages. SoundCloud constants stay in `lib/data/sources/soundcloud/soundcloud_api.dart`, and YouTube client values stay in `innertube_clients.dart`.
- Exact strings:
  - "Playlists can't be downloaded yet. Paste the link of a single song."
  - "This link isn't a song on YouTube or SoundCloud"
  - "YouTube: <reason>" (as today)
  - The SoundCloud resolve messages ("Protected: this track can't be downloaded" etc., existing).
- YouTube id: exactly 11 characters from `[A-Za-z0-9_-]`. `sourceKey` is `youtube:<id>` or `soundcloud:<id>`, the same keys as search results, so "In Library" matches.
- Links are never added to recent searches. The tab is not switched.

## Review Focus

1. **A link with tracking parameters or a timestamp**, e.g. `https://youtu.be/5qZQEq_C3vc?si=abc&t=42` or `https://soundcloud.com/sry4u/track?si=x&utm_source=clipboard`. The same song must open. Test in Task 1.
2. **Leading or trailing whitespace or a newline from the clipboard.** It is still recognized. Test in Task 1.
3. **A watch link that also has `&list=`**, e.g. `watch?v=ID&list=RD…` (YouTube "Mix" links, which are common). The video must open, not the playlist error. Test in Task 1.
4. **Pasting while a search or another lookup is running.** Only the latest action wins, and a late lookup must not open a sheet after the user typed something else. Test in Task 3.
5. **A normal query that contains a dot or slash**, e.g. "AC/DC", "Mr. Brightside", "youtube rewind". It is searched as text, not treated as a link. Test in Task 1.

### Task 2: Look up one song by link

**Files:**

  - `test/data/sources/youtube_parsers_test.dart`
  - `test/data/sources/youtube_sources_test.dart`
  - `test/data/sources/soundcloud_source_test.dart`

**Interfaces:**
- Consumes: `OnlineLink`, `YoutubeLink`, `SoundcloudLink`, `playlistLinkMessage`, `notASongLinkMessage` (Task 1).
- Produces:
  - `OnlineSource.lookup(OnlineLink link) → Future<OnlineResult>`. A link of the wrong kind throws `ArgumentError`.
  - `OnlineResult parseVideoDetails(Map<String, Object?> player)` in youtube_parsers.dart:
    - a `playabilityStatus` other than OK → `OnlineError('YouTube: <reason>')`, the same as `parsePlayer`
    - no `videoDetails` → `changedError('YouTube')`
    - result fields: source `youtube`, `title`, channel = `author`, duration = `lengthSeconds`, thumbnail and coverUrl = the last (largest) of `thumbnail.thumbnails`, `squareCover: false`, empty `tags`
    - subtitle is the channel name. Without views data it shows just the author.
  - `YoutubeSource.lookup` and `YoutubeMusicSource.lookup` both call `_client.player(videoId)` and then `parseVideoDetails`.
  - `SoundcloudClient.resolveUrl(Uri url) → Future<Map<String, Object?>>` calls `GET /resolve?url=<url>` through `_api`. The path constant is `resolvePath = '/resolve'` and the parameter is `urlParam = 'url'`.
  - `SoundcloudSource.lookup` maps the answer:
    - `kind == 'track'` → `parseSoundcloudTrack`. If availability is not `available`, it throws `OnlineError` with the same message `resolve` uses for that availability.
    - `kind == 'playlist'` → `OnlineError(playlistLinkMessage)`.
    - other kinds, or `HttpStatusError` 404 → `OnlineError(notASongLinkMessage)`.
  - `FakeOnlineSource`: `final lookups = <OnlineLink>[]`, `final linkResults = <String, OnlineResult>{}` (keyed by video id or by link URL string), `Object? lookupError`, and `Completer<void>? lookupGate`.

  - `parseVideoDetails on player_login_required.json throws "YouTube: …"`.
  - `YoutubeSource.lookup asks the player for the link's id`, using the fake transport.
  - SoundCloud, serving `soundcloud_track.json` for `/resolve`:

    - `kind user → notASongLinkMessage`.
    - `404 → notASongLinkMessage`.
    - `a protected track → "Protected: this track can't be downloaded"`, using an edited copy of the fixture.
