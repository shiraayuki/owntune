# M2 v0.4.1 Background Playback Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Background playback, lock-screen / Control Center / Android notification controls, and restoring the player (paused at the saved position) after a restart.

**Architecture:** audio_service's `BaseAudioHandler` sits behind a `SystemControls` interface and forwards system commands to the existing `PlayerController`; a sync provider publishes the current song and play state to it. The controller follows play-state changes the engine makes on its own, and saves a `PlayerSnapshot` (JSON in `settings_entries`) that `startUp()` loads and the controller restores when the first library snapshot arrives.

**Tech Stack:** Flutter 3.50, flutter_riverpod 3, just_audio 0.10.6, audio_service 0.18.19, drift.

**Spec:** `docs/superpowers/specs/2026-11-19-m2-v0.4.1-background-design.md`

## Global Constraints

- Everything in English; `package:material_ui` / `package:cupertino_ui` imports; `flutter analyze` → "No issues found!".
- Unit/widget tests never touch audio_service or just_audio: `pumpApp` overrides `audioEngineProvider`, `systemControlsProvider` (default `NoSystemControls`) and `playerStateStoreProvider`.
- Startup errors → `StartupFailed`; a malformed saved player state → ignored (empty player).
- Restore is always **paused** at the saved position.
- Saving: on queue/index/repeat change, pause, seek, and every 5 s of playback.
- No shuffle, no Linux system controls.

## Review Focus

1. **Restore while songs were deleted meanwhile** — dropped like any deletion; current gone → following entry at 0:00, none left → empty player. Test in Task 2.
2. **System pause (phone call) then UI play** — controller state must not drift from the engine's; after an engine-side pause the mini player shows Play. Test in Task 1.
3. **Malformed or old saved JSON** — ignored, never a crash or startup failure. Test in Task 2.
4. **Lock-screen Previous/Next at queue edges** — Next absent from controls on the last song with repeat off; Previous restarts after 3 s. Test in Task 3.
5. **Seek from the lock screen** — position published again so the system scrubber does not jump back. Test in Task 3.

### Task 2: Save and restore the player

**Files:** Create `lib/player/player_snapshot.dart`; Modify `lib/app/startup.dart`, `lib/main.dart`, `lib/app/providers.dart`, `lib/player/player_controller.dart`, `test/support/fakes.dart`; Test `test/player/player_snapshot_test.dart`, `test/player/player_restore_test.dart`, `test/app/startup_test.dart`

**Interfaces:**
```dart
class PlayerSnapshot {
  const PlayerSnapshot({required this.trackIds, required this.index, this.source, this.repeat = QueueRepeat.off, this.position = Duration.zero});
  final List<int> trackIds; final int index; final String? source; final QueueRepeat repeat; final Duration position;
  String toJson(); static PlayerSnapshot? tryParse(String? json); // null for missing/malformed/out-of-range index
}
abstract interface class PlayerStateStore { Future<PlayerSnapshot?> load(); Future<void> save(PlayerSnapshot? snapshot); } // null deletes
class DbPlayerStateStore implements PlayerStateStore { DbPlayerStateStore(AppDatabase db); } // key 'player.state'
final playerStateStoreProvider = Provider<PlayerStateStore>((ref) => DbPlayerStateStore(ref.watch(databaseProvider)));
final initialPlayerSnapshotProvider = Provider<PlayerSnapshot?>((ref) => null);
class FakePlayerStateStore implements PlayerStateStore { PlayerSnapshot? saved; int saves; }
```
- `StartupReady` gains `PlayerSnapshot? player`; `startUp` loads it after the settings (a load error → null, not a failure). `main` overrides `initialPlayerSnapshotProvider`.
- Controller: when the first non-null tracks list arrives and the initial snapshot exists and the queue is empty → build the queue (`PlayQueue.of(ids, start: index, source, repeat)` then `retain`), `_start(queue, play: false)`, then `seek(position)` unless the current entry changed through retain (then 0). Saving: after every `state` change that changes queue entries/index/repeat (compare with the last saved), on `togglePlay` to paused, on `seek`, and from the position stream when ≥ 5 s since the last save while playing. Empty queue → `save(null)`. Save errors are swallowed (best effort).

### Task 3: System controls

**Files:** Create `lib/player/system_controls.dart`; Modify `lib/app/startup.dart`, `lib/main.dart`, `lib/app/app_shell.dart` (keep the sync provider alive: `ref.watch(systemControlsSyncProvider)` in `OwntuneApp.build`), `test/support/fakes.dart`; Test `test/player/system_controls_test.dart`, `test/app/startup_test.dart`

**Interfaces:**
```dart
class NowPlaying { // what the system shows
  const NowPlaying({required this.track, this.coverFile, required this.playing, required this.position, required this.hasNext});
  final Track track; final File? coverFile; final bool playing; final Duration position; final bool hasNext;
}
abstract interface class SystemCommands { Future<void> play(); Future<void> pause(); Future<void> next(); Future<void> previous(); Future<void> seek(Duration p); }
abstract interface class SystemControls { void connect(SystemCommands commands); void show(NowPlaying? now); }
class NoSystemControls implements SystemControls {}
class AudioServiceControls implements SystemControls { static Future<AudioServiceControls> init(); } // AudioService.init with channel id 'dev.owntune.playback', name 'Playback'
final systemControlsProvider = Provider<SystemControls>((ref) => NoSystemControls());
final systemControlsSyncProvider = Provider<void>(...); // connects the controller, calls show() on track/playing/hasNext changes and on position jumps > 2 s vs. expected
class FakeSystemControls implements SystemControls { SystemCommands? commands; final shown = <NowPlaying?>[]; }
```
- `PlayerController` implements `SystemCommands` via an adapter in the sync provider (play/pause → togglePlay when needed, next, previous, seek).
- `AudioServiceControls.show`: `mediaItem` (id = track id, title via `displayTitle`, artist via `displayArtist`, album, duration, `artUri: Uri.file(cover)`), `playbackState` (controls: previous, play/pause, next only if `hasNext`; `systemActions: {MediaAction.seek}`; `androidCompactActionIndices`; processingState ready; `updatePosition`). `show(null)` → idle state, no media item.
- `startUp({..., Future<SystemControls> Function()? initSystemControls})`: default `AudioServiceControls.init` on iOS/Android, `NoSystemControls` elsewhere; `StartupReady` gains `controls`; `main` overrides `systemControlsProvider`.

- [ ] Failing tests (`system_controls_test.dart`, widget tests with `pumpApp(..., overrides: [systemControlsProvider.overrideWithValue(fake)])`): `shows the playing song`; `system play, pause, next and previous reach the player`; `next is not offered on the last song with repeat off` (`shown.last.hasNext == false`); `a seek from the system is published again` (`commands.seek(90 s)` then position event 90 s → a new `shown` with position ≈ 90 s); `nothing shown when the queue empties` (`shown.last == null`).
