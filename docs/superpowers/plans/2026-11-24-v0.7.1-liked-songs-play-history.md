# v0.7.1 Liked Songs and Play History Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Like songs (heart in Now Playing, song menu, Add to Playlist sheet) with a Liked Songs collection, and silently record a play history (30-second rule, listened time, where it was played from) for the Home tab of v0.7.2/v0.7.3.

**Architecture:** drift schema v4 adds `tracks.liked_at` and a `plays` table. The queue's `String? source` becomes a `QueueSource` (kind, key, label), and each `QueueEntry` gets a `queued` flag for Play Next/Later. A pure `ListenSession` does the listening arithmetic, and `PlayerController` owns one session at a time. It writes the session's row through `PlayRepository` on a single sequential write chain and counts the play (`markPlayed`) once the session reaches 30 s.

**Tech Stack:** Flutter 3.50 / Dart 3.14, flutter_riverpod 3 (no codegen), drift + build_runner, flutter_test with `FakeAudioEngine` and `pumpApp`.

**Spec:** `docs/superpowers/specs/2026-11-24-v0.7.1-liked-songs-play-history-design.md` (read it first; this plan argues from it).

## Global Constraints

- Imports: `package:material_ui/material_ui.dart` and `package:cupertino_ui/cupertino_ui.dart` (icons: `CupertinoIcons`), never `flutter/material.dart` / `flutter/cupertino.dart`.
- Everything is in English: code, comments, tests, UI strings and commit messages.
- `flutter analyze` must report "No issues found!"; `dart format` clean.
- After the drift schema change: `dart run build_runner build --delete-conflicting-outputs`, and commit `lib/data/db/database.g.dart`.
- Logic must be testable without Rust: dependencies come through Riverpod providers, and tests override them.
- History writes never block or break playback: they are not awaited on the playback path, and every error is swallowed (`.catchError((Object _) {})`). Like/unlike errors are shown in a dialog (`AlertDialog.adaptive` + `SelectableText('$e')` + `DialogAction(label: 'OK')`, as for "Remove from Playlist").
- Values from the spec: a play counts at **30 s** heard (or at the end of a song shorter than 30 s). A row is written only once the session has **≥ 1000 ms** heard. A pause of **≥ 30 min** ends the session. Saving happens at the existing save points (every **5 s** of playback, on pause, on queue changes) and at the session end. A position step larger than **3 s** is ignored (a seek or a hiccup).
- Every commit message ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Same song twice in a row** (repeat one, or the same track queued twice). Each round or entry is its own session with its own row and its own count; the second never updates the first's row. → Task 5 test `repeat one writes one row per round`.
2. **Pausing at 25 s and resuming after 31 min.** The first session stays uncounted (25 s); the new one starts at zero, so listening another 10 s does not reach 30 s, and nothing counts. → Task 5 test `a long pause starts a new session and resets the count`.
3. **Seeking with the scrubber or system controls while playing**, and "Previous" restarting the song after 3 s. None of it adds listened time, and the restart does not start a new session. → Task 4 test `a seek resets the baseline` plus Task 5 test `previous restarting the song keeps the session`.
4. **Liking from Now Playing while the Liked Songs page is open underneath.** The page drops or gains the song right away, because both read `tracksProvider`. → Task 7 test `unliking removes the song from the page`.
5. **A saved player state from v0.7.0** (label only, no kind, no queued positions) restores with its label shown, kind `other`, and no entry flagged. → Task 3 test `an old snapshot restores as other`.

  class ListenSession {
    ListenSession({required int trackId, required int durationMs, required QueueSourceKind sourceKind, String? sourceKey});
    final int trackId; final int durationMs; final QueueSourceKind sourceKind; final String? sourceKey;
    DateTime? get startedAt;      // set by the first step that adds time

### Task 5: Record listens in PlayerController

**Files:**
- Modify: `lib/player/player_controller.dart`
- Test: `test/player/player_controller_test.dart` (the setUp also overrides `playRepositoryProvider` with a `FakePlayRepository`, and `clockProvider` with a test clock `var now = DateTime(2026, 11, 24, 20); … () => now`)

**Interfaces:**
- Consumes: `ListenSession` (Task 4), `PlayRepository` and `clockProvider` (Task 2), `QueueEntry.queued` and `QueueSource` (Task 3), `TrackRepository.markPlayed(int id)` (existing: play count + 1, `last_played_at` now).
- Produces: no new public API. `markPlayed` is now called when a session becomes counted, no longer in `_onCompleted`.

Behaviour (from the spec, *Listen sessions*):
- `_start` ends the old session (final write) and creates a new one for `queue.current`, except when called from `reloadIfCurrent` for the same entry key: then only `resetBaseline`. The new one gets kind/key from `entry.queued ? (queued, null) : queue.source ?? (other, null)` and the track's `durationMs`.
- `_onPosition`: while `state.playing`, `session.advance(p, clock())`. When that returns true: `markPlayed(trackId)` (fire-and-forget, errors swallowed) and a write.
- `seek`: `session.resetBaseline(position)`.
- `_onCompleted`: `session.complete()`, counting if true, then end the session (final write) before moving on.
- `_stop`: end the session.
- Pause and resume: remember `clock()` when playing becomes false (`togglePlay` and `_onEnginePlaying`). When it becomes true again after **≥ 30 min** and the session has a `startedAt`, end it and start a fresh one for the same entry, with the baseline at the current position.
- Writes: `_save()` and session end call `_writeSession(session)`. This does nothing while `listenedMs < 1000`. Otherwise it appends to one `Future<void> _writes` chain: `rowId == null ? rowId = await insert(...) : await update(rowId, ...)`, with every error swallowed.
