# Paste a link into Search Online (short design)

Date: 2026-11-25 · Release: **v0.8.1** · Follows v0.8.0 (SoundCloud).

## Intent

The user copies a YouTube or SoundCloud link (from the app, a browser, a friend) and pastes it into the Search Online field. Instead of searching, owntune finds that one song and **opens the Download sheet right away** (the user picked this over showing it as a single result row). It is one tap to Download.

## Decided

- **Behaviour A:** after a link is pasted or submitted, a spinner shows below the field, then the Download sheet opens for the song. Nothing is added to the result list.
- Works on **every tab**. The source comes from the link, and the tab is not switched.
- **Supported links** (any `http`/`https`, with or without `www.`/`m.`, extra query parameters ignored):
  - YouTube: `youtube.com/watch?v=<id>`, `music.youtube.com/watch?v=<id>`, `youtu.be/<id>`, `youtube.com/shorts/<id>`, `youtube.com/live/<id>`, `youtube.com/embed/<id>`. The id is 11 characters from `[A-Za-z0-9_-]`. A `list=` next to a `v=` is ignored, so the video is used.
  - SoundCloud: `soundcloud.com/<user>/<track>` (also `m.soundcloud.com`) and short links `on.soundcloud.com/<code>`. The short links redirect, which `dart:io` follows for GET.
- **Rejected with a message** (shown in the existing error state, without Retry):
  - Playlists: YouTube `playlist?list=` or a link with `list=` but no `v=`, and SoundCloud `/sets/`. Message: "Playlists can't be downloaded yet. Paste the link of a single song."
  - Any other link (other sites, YouTube channels, SoundCloud user pages): "This link isn't a song on YouTube or SoundCloud".
- **YouTube lookup:** the player call we already make (`InnertubeClient.player`). From `videoDetails` it builds an `OnlineResult` like a YouTube *video* result:
  - fields: `title`, `author` as channel, `lengthSeconds`, the largest thumbnail, `sourceKey` `youtube:<id>`, source `OnlineSourceId.youtube`, `squareCover: false`
  - so the sheet guesses title and artist with `guessTags`; " - Topic" is already stripped from the channel
  - there is no album, including for `music.youtube.com` links; the user can type one in the sheet
  - a `playabilityStatus` other than OK fails with "YouTube: <reason>", as for downloads.
- **SoundCloud lookup:** `GET api-v2.soundcloud.com/resolve?url=<link>&client_id=…` returns the full track object (checked 2026-11-25), parsed with `parseSoundcloudTrack`.
  - A `kind` other than `track` gets the playlist message (for `playlist`) or the "isn't a song" message (for anything else).
  - A track whose availability is not `available` does not open the sheet. Instead it shows its resolve message ("Protected: this track can't be downloaded", etc.).
  - A 404 from resolve shows "This link isn't a song on YouTube or SoundCloud".
- **Trigger:**
  - Submitting the field: Enter or the keyboard's search key.
  - A paste: the text grows by more than one character at once and is then a link.
  - Typing a URL letter by letter does not trigger until submit.
- Links are **not** added to recent searches.
- A song that is already in the library still opens the sheet, which shows "In Library" (existing behaviour).

## Non-goals

- Whole playlists, albums or sets (a later release); "Open with …" or the share sheet (M5).
- An album for YouTube links.

## Approach

One pure parser, `parseOnlineLink(String) → OnlineLink?` (sealed: `YoutubeLink(videoId)`, `SoundcloudLink(Uri)`, `UnsupportedLink(message)`; null = not a link, so search as usual). `OnlineSource` gets `Future<OnlineResult> lookup(OnlineLink link)`, implemented by `YoutubeSource` (and `YoutubeMusicSource`, which shares the client and delegates) and `SoundcloudSource`. The screen picks `sources[youtube]` or `sources[soundcloud]` by link type.

Rejected alternatives:
- Looking up YouTube Music metadata for an album: it needs another client call (`next`/browse) and new parsing for a field the user can type.
- A separate link screen: the search field is where people paste.
