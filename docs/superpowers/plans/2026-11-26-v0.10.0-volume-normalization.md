# v0.10.0 Volume Normalization Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Measure every song's integrated loudness once in Rust and, with the "Normalize Volume" switch on, play loud songs attenuated to −14 LUFS.

**Architecture:** A Rust function decodes a file with symphonia and measures it with ebur128 (cancellable through a job id). A foreground-only `LoudnessMeasurer` in Dart walks the unmeasured tracks newest first, one at a time, and stores the result in a new `track_loudness` table. `PlayerController` reads a song's loudness when it loads the song and sets the engine volume from a pure gain function before it plays.

**Tech Stack:** Rust (symphonia, ebur128, flutter_rust_bridge 2.13.0), Flutter/Dart (drift, Riverpod 3, just_audio).

**Spec:** `docs/superpowers/specs/2026-11-26-v0.10.0-volume-normalization-design.md`

**Deviation from the spec (planner's call):** the spec puts `loudness_lufs` / `loudness_attempt` on `tracks`. This plan puts them in their own table `track_loudness` instead. Every write to `tracks` re-emits `tracksProvider`, and that re-derives the whole library (`Library.from`, sorting, playlists). One write per measured song during the first pass over a large library would do that every second or two. The meaning is unchanged: `lufs` null = not measured, `failed_version` = the measurer version that last failed.

## Global Constraints

- Everything in English (code, comments, tests, commit messages, UI strings).
- `flutter analyze` must report "No issues found!"; `cargo clippy -- -D warnings` and `cargo fmt --check` clean.
- New crates pinned exactly in `rust/Cargo.toml` (`=x.y.z`); flutter_rust_bridge stays `=2.13.0`.
- Imports: `package:material_ui/material_ui.dart` and `package:cupertino_ui/cupertino_ui.dart`, never `package:flutter/material.dart` or `cupertino.dart`.
- Generated code is committed: run `flutter_rust_bridge_codegen generate` after Rust API changes and `dart run build_runner build --delete-conflicting-outputs` after schema changes.
- Target level **−14 LUFS**, attenuation only: `volume = min(1.0, 10^((−14 − lufs) / 20))`; not measured / failed / switch off → `1.0`.
- Switch: group **Playback**, label **Normalize Volume**, footnote **"Plays all songs at a similar loudness."**, default **on**.
- Measuring never runs while the app is in the background; a cancelled measurement stores nothing.
- Import, download and playback never wait for or fail because of a measurement.
- Work on branch `v0.10.0-volume-normalization` (create it from `main` before Task 1).

## Review Focus

1. A song is deleted while it is being measured → no `track_loudness` row is left for it, nothing throws (Task 2: `saveMeasured`/`saveFailed` on a missing track write nothing; Task 3: the measurer moves on).
2. The app goes to the background in the middle of a 2 h mix → the Rust job is cancelled, nothing is stored, and the same song is measured again from the start on resume (Task 3).
3. A measurement for the current song lands mid-song → the volume does not jump; it applies from the next load (Task 5).
4. The switch is flipped while a song plays → the volume follows at once, both ways (Task 5).
5. A database error inside the measurer → the loop stops quietly (no tight retry loop, no exception into the app), and the next trigger tries again (Task 3).

**Interfaces:**
- Consumes: Task 1 `measureLoudness`, `newLoudnessJob`, `cancelLoudness`, `LoudnessResult`; Task 2 `LoudnessRepository`, `loudnessRepositoryProvider`; existing `storageProvider`, `tracksProvider`.
- Produces:
  - `abstract interface class LoudnessMeter { int newJob(); Future<LoudnessResult> measure(String path, int job); void cancel(int job); }`
  - `class RustLoudnessMeter implements LoudnessMeter`, which calls the generated functions.
  - `final loudnessMeterProvider = Provider<LoudnessMeter>((ref) => RustLoudnessMeter());`
  - `const kLoudnessMeasurerVersion = 1;`
  - `class LoudnessMeasurer { LoudnessMeasurer({required LoudnessRepository repo, required LibraryStorage storage, required LoudnessMeter meter, bool foreground = true}); void kick(); void setForeground(bool foreground); Future<void> get idle; void dispose(); }`
  - In `test/support/fakes.dart`: `class FakeLoudnessRepository implements LoudnessRepository { FakeLoudnessRepository({List<Track> pending = const [], Map<int, double> lufs = const {}}); bool throwOnNext; bool throwOnLufs; final measured = <(int, double)>[]; final failed = <(int, int)>[]; }`. `lufs` is mutable so tests can change it mid-song (Task 5 uses it). And `class FakeLoudnessMeter implements LoudnessMeter` with `measured` paths, `cancelled` jobs, and one `Completer<LoudnessResult>` per call.
  - `final loudnessMeasurerProvider = Provider<LoudnessMeasurer>(...)`: builds the measurer and starts in the foreground unless `WidgetsBinding.instance.lifecycleState` is `hidden`, `paused` or `detached`. An `AppLifecycleListener(onStateChange: …)` calls `setForeground(state == resumed || state == inactive)`. `ref.listen(tracksProvider, (_, _) => m.kick(), fireImmediately: true)`. `ref.onDispose` disposes the listener and the measurer.

Loop behaviour (what the tests pin): one measurement at a time. Each round asks `nextUnmeasured(kLoudnessMeasurerVersion)`; `null` ends the loop. Otherwise it measures `storage.audioFile(track.fileName).path` with a fresh `meter.newJob()`.
- `lufs` set → `saveMeasured`.
- `cancelled` → store nothing and end the loop.
- Otherwise, or if `measure` throws → `saveFailed(track.id, kLoudnessMeasurerVersion)`.

A `kick()` while running makes the loop look again after the current song. `setForeground(false)` cancels the running job and keeps a new loop from starting. `setForeground(true)` kicks. An exception from the repository ends the loop silently. `dispose()` cancels the running job. `idle` completes when no loop runs.

- [ ] **Step 1: Write the failing tests** in `test/loudness/loudness_measurer_test.dart`. Use `FakeLoudnessRepository` (a list of pending `Track`s returned newest-first, recorded saves, optional `throwOnNext`) and `FakeLoudnessMeter` (each `measure` returns a `Completer` the test completes; records `measured` paths and `cancelled` jobs):
  - `measures pending tracks newest first, one at a time`: two pending → the first `measure` is in flight and the second does not start until it completes; saves in order.
  - `stores a failure with the measurer version`: result `lufs: null, message: 'x'` → `saveFailed(id, 1)`.
  - `stores a failure when measure throws`.
  - `going to the background cancels and stores nothing`: during a measure, `setForeground(false)` → `cancelled` contains that job; completing it with `cancelled: true` → no save, no further `measure`. Then `setForeground(true)` → the same path is measured again.
  - `does not start while in the background`: `foreground: false`, `kick()` → no `measure`.
  - `a kick while measuring picks up tracks added meanwhile`.
  - `a repository error ends the loop quietly`: `throwOnNext` → `idle` completes without error, no `measure`; the next `kick()` runs again.
  - `dispose cancels the running job`.
  - Widget test via `pumpApp` (with an overridden `FakeLoudnessRepository` holding one pending track and a `FakeLoudnessMeter`): the meter is asked for `storage.audioFile(fileName).path`. Then `t.binding.handleAppLifecycleStateChanged(AppLifecycleState.paused)` → the job is cancelled.
