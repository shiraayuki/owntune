# v0.7.2 — Home: For You (design)

## Intent

Second of the three Home releases (v0.7.1 Liked Songs + play history ✅, **v0.7.2 For You**, v0.7.3 Stats). Home stops being a placeholder and becomes the **start tab**: a quick start into music — what was played last, the queue to continue, shuffle buttons, and rows built from play counts, last played and date added. Mockups: `docs/mockups/home-v1/01-for-you.html`, `02-for-you-scrolled.html`, `05-empty.html` (Spotify's Home is the reference the user likes for player interactions).

The play history (`plays` table, since v0.7.1) is empty right after the update, so every history-based part needs a sensible fallback; nothing on Home may look broken on day one.

## Goals

- The app opens on **Home** (tab index 0) instead of Library.
- Home has sub-tabs **For You | Stats** (`TextTabs`, as in Library). Stats is a placeholder in this release.
- The title row shows a **greeting by time of day** on Home (both sub-tabs) instead of "Home"; the tab bar label stays "Home".
- For You, top to bottom (mockups 01/02):
  1. **Tiles**: up to 6 recently played sources (albums, artists, playlists, Liked Songs) in a 2×3 grid, filled up from Liked Songs, playlists and recently added albums when the history has fewer.
  2. **Continue listening**: the player's current queue while it is paused.
  3. **Shuffle All / Shuffle Liked** buttons.
  4. Rows **On Repeat**, **Recently Added**, **Rediscover**, **Never Played**, each a horizontal row of cards with a header that opens the full list.
- **Empty library**: For You shows the empty state of mockup 05 with **Import Music** and **Search Online**.

## Non-goals

- Stats content (v0.7.3). Recommendations from outside the library, "Made for you" mixes, daily mixes.
- Persisting the selected sub-tab across restarts.
- Live refresh of the greeting while the screen stays open (it updates on the next rebuild).
- Editing, hiding or reordering Home sections; pull to refresh.
- Rediscover/Never Played for albums or artists (songs only).

## Anti-goals

- Home slowing down app start or scrolling (history queries are indexed, limited, and run in SQL — never "load all plays into Dart").
- Showing deleted songs, renamed-away albums or deleted playlists anywhere on Home.
- Sections that show a heading with nothing under it; an empty-looking Home on the day of the update.
- Recording Home itself as a source that pollutes the tiles (rows played from Home are not albums/playlists).

## Constraints

- CLAUDE.md rules: logic testable on Linux without Rust (providers overridden in tests, `pumpApp`), English everywhere, `material_ui` / `cupertino_ui` imports, errors visible (a failed Home load shows an error text like the other tabs, never a crash).
- `plays.source_key` for albums contains `\u0000` (artist key NUL title key). SQL may only compare/group it by equality; splitting happens in Dart (v0.7.1 ruling).
- The 30-day window and all "ago" texts use the injected `clockProvider`, so tests control time.

## Approaches

1. **History aggregates in SQL, library-based rows and composition in Dart** *(chosen)*. A small `HomeRepository` runs two watched queries over `plays` (recent sources; top tracks since a date) using the `plays_started` index. Recently Added, Rediscover and Never Played come from `Library` (track fields `addedAt`, `playCount`, `lastPlayedAt`) like every other view. Pure Dart functions combine both, resolve keys against the current library/playlists, apply fallbacks and limits. Scales with a growing history; easy to unit-test.
2. Load all plays into Dart and aggregate there. Simple, but grows without bound (tens of thousands of rows after a few years) and rebuilds on every play. Rejected.
3. A precomputed aggregate table updated on every play. A second source of truth that can drift from `plays`; unnecessary at this size. Rejected.

## Design

### Shell

- `_AppShellState._index` starts at the Home tab (0); the "opens on Library while Home is a placeholder" comment goes.
- `_TitleRow.title` on the Home tab is `greeting(now)`:
  - 05:00–11:59 → "Good morning"
  - 12:00–17:59 → "Good afternoon"
  - otherwise → "Good evening"
- Home keeps the existing title row actions ("…" with Settings, "+"). *(Orchestrator's call)* Screens opened from the title row (e.g. "+" → Search Online) get the tab label "Home" as their back label, never the greeting.

### Home tab

`HomeScreen` becomes a `Column` with `TextTabs<HomeSection>` (For You | Stats) above an `IndexedStack`, like `LibraryTab`. The selected sub-tab lives in the shell state for the session (default For You). Unlike Library, the sub-tabs stay visible with an empty library (mockup 05).

- **Stats** sub-tab (placeholder): `PlaceholderState` with a chart icon, "Stats are coming", "Listening time, top artists and more arrive in the next version."
- **For You** with an empty library (no tracks): the mockup 05 empty state: "Your music lives here" / "Import files you already have, or find songs on YouTube." (SoundCloud is left out until it exists), buttons **Import Music** (same action as "+" → Import Music) and **Search Online** (`openSearchOnline(context, backLabel: 'Home')`).
- **For You** with a library: a vertical scroll of the sections below; each section is hidden when it has no items. The mini player and tab bar stay as on other tabs.

### Data

`HomeRepository(AppDatabase db)` (in `lib/home/`), exposed via `homeRepositoryProvider`:

- `Stream<List<RecentSource>> watchRecentSources({required DateTime since, int limit = 20})`: distinct `(source_kind, source_key)` over `plays` where `source_kind IN ('album','artist','playlist','liked')` and `started_at >= since` (the last 365 days, so the query uses the `plays_started` index), ordered by `MAX(started_at)` descending. `RecentSource(kind, key, lastPlayedAt)`.
- `Stream<List<TrackPlayCount>> watchTopTracks({required DateTime since, int limit = 50})`: `track_id`, `COUNT(*)` of rows with `counted = 1 AND started_at >= since`, ordered by count desc, then latest play desc. `TrackPlayCount(trackId, plays)`.
- Both are drift `customSelect(...).watch()` with `readsFrom: {plays}`, so they re-run after each written play. The player also updates the open row every five seconds, so both streams are `.distinct()` on their list (`ListEquality`) and emit only when the result changes.

A pure function (`lib/home/for_you.dart`) builds the view model from `Library`, the resolved `PlaylistView`s, liked songs, the two streams and `now`:

```
ForYou buildForYou({
  required Library library,
  required List<PlaylistView> playlists,
  required List<Track> liked,
  required List<RecentSource> recent,
  required List<TrackPlayCount> topRecent,
  required DateTime now,
})
```

`forYouProvider` (`Provider<AsyncValue<ForYou>>`) combines them. *(Orchestrator's call)* `since` is day-granular — local midnight of today minus 30 days for top tracks, minus 365 days for recent sources — computed inside `forYouProvider` from the clock, and both history streams are `autoDispose` families keyed by that date, so a stream is not recreated on every play (which would make For You flicker into loading); it switches to the new window on the first rebuild after midnight. While a history stream has no value yet, `forYouProvider` stays loading; a failing one counts as empty history.

*(Orchestrator's call)* Every `plays` row counts for the tiles, also short samples (≥ 1 s): a source the user opened and listened to briefly is still "recently played", as on Spotify.

### Sections

**Tiles** (max 6, 2 columns × 3 rows, each tile: small artwork + title, like mockup 01)
- From `recent` in order, resolved:
  - album: split the key on `\u0000` → `AlbumKey` → `library.album(key)`
  - artist: `library.artist(key)`
  - playlist: `int.tryParse(key)` → playlist by id
  - liked: shown only while at least one song is liked
- Unresolvable entries (deleted, renamed) are skipped.
- **Fill-up** when fewer than 6: Liked Songs (if any liked and not yet shown), then playlists (newest created first), then albums by Recently Added order. No duplicates.
- Artwork:
  - album → its cover
  - playlist → `PlaylistArtwork`
  - Liked Songs → `LikedArtwork`
  - artist → `avatarCover`, round
- Tap opens the album/artist/playlist/Liked Songs page with back label "Home".

**Continue listening** (one card)
- Shown when the player queue is not empty and not playing, and hidden while playing (the mini player covers that case).
- Eyebrow "Continue listening". Title is the queue source's label; when there is none, or when the current entry is `queued`, it is the current song's title. Subtitle "Song {index+1} of {count} · {current song title}".
- A thin progress bar shows position / duration of the current song.
- The play button and a tap on the card both call `togglePlay()`, which resumes where it was.

**Shuffle All / Shuffle Liked** (two buttons side by side)
- Shuffle All: `playList(all songs, start: 0, source: QueueSource.songs(), shuffle: true)`.
- Shuffle Liked: same with the liked songs and `QueueSource.liked()`. It is disabled when nothing is liked.

**On Repeat** (songs, max 10)
- Source: `topRecent` resolved against the library (deleted tracks skipped). Each card's subtitle is "{n} plays" ("1 play" for one), using the 30-day count.
- **Fallback** while the history is young: if fewer than 4 songs resolve, use all-time `playCount > 0`, sorted by `playCount` desc then `lastPlayedAt` desc, with the all-time count as the subtitle.

**Recently Added** (albums, max 10)
- Albums sorted by the newest `addedAt` among their tracks, descending; ties (`addedAt` is stored in whole seconds) go to the album with the highest track id. Card subtitle: the album artist.
- Tap opens the album.

**Rediscover** (songs, max 10)
- Songs with `playCount >= 3` and `lastPlayedAt` older than 60 days, sorted by `playCount` desc.
- Subtitle "Last played {n} mo ago", where n = whole months (days / 30, at least 2).

**Never Played** (songs, max 10)
- Songs with `playCount == 0`, newest added first. Subtitle: the artist.

**Song cards** (On Repeat, Rediscover, Never Played)
- A tap plays that row's songs, starting at the tapped one.
- The source is a plain `QueueSource(QueueSourceKind.other, '<section title>')`, so plays from Home do not show up as album/playlist tiles.
- Long-press opens the song menu (`SongMenuScope(backLabel: 'Home')`).

**Section headers with "›"** open a full-list page (`NavRow` back "Home", title = section title):
- Songs: up to 50 items as `SongRow`s, with the same play-from-tap behaviour and the same source.
- Recently Added: up to 50 albums as `LinkRow`s with cover, title and artist.

### Errors

If any input of `forYouProvider` fails, For You shows `LoadError(title: 'Could not load Home', …)` (the shared widget from v0.7.0's review). Stream errors from `HomeRepository` fall back to empty history instead of an error, because Home must still work without history.

### Testing

- **Unit**
  - `buildForYou`:
    - tile resolution, order and dedupe
    - deleted or renamed sources skipped
    - fill-up order
    - On Repeat fallback below 4 songs
    - Rediscover thresholds (exactly 60 days, playCount 2 vs 3)
    - Never Played order
    - Recently Added order
    - Liked tile only when something is liked
    - the album key split on NUL
  - `greeting` boundaries: 04:59, 05:00, 11:59, 12:00, 17:59, 18:00.
  - `HomeRepository` against an in-memory database:
    - `recent` ordering and distinctness
    - non-source kinds (songs/search/queued/other) excluded
    - `top` counting only `counted` rows since the date
    - both streams re-emit after a new play row
- **Widget**
  - The app opens on Home and the greeting shows.
  - The For You / Stats switch works.
  - Empty library: the empty state buttons call import / open Search Online.
  - Continue listening shows when paused, hides while playing, and its tap resumes.
  - Shuffle All / Shuffle Liked start the right queue; Shuffle Liked is disabled without likes.
  - Tapping tiles opens the right page.
  - A song card tap plays the row from that song.
  - The "›" header opens the full list.
  - Empty sections are hidden.
  - A failing load shows the error.
- **Integration**
  - Home on the real database after a few recorded plays: tiles and On Repeat appear.
