# v0.6.0 YouTube Download Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** "+" → Search Online finds songs (YouTube Music) and videos (YouTube), downloads the M4A audio and adds it to the library with title, artist, album and cover.

**Architecture:** A small own innertube client in Dart (`lib/data/sources/`) behind an `OnlineSource` interface: two searches (WEB_REMIX, WEB) and one player call (VISIONOS) that yields a direct itag-140 URL. An app-wide `DownloadController` (`lib/download/`) runs one job at a time: resolve → chunked download to a temp file → cover → tags + cover written by Rust → the existing `Importer` (now with a source key per file). The DB gets `tracks.source_key` (first migration) for "In Library".

**Tech Stack:** Flutter 3.50, flutter_riverpod 3, drift, `dart:io` HttpClient, `image` (new: cover crop/re-encode), Rust lofty 0.25.5 via flutter_rust_bridge 2.13.0.

**Spec:** `docs/superpowers/specs/2026-11-20-v0.6.0-youtube-download-design.md`

## Global Constraints

- English everywhere (code, UI, commits); `package:material_ui` / `package:cupertino_ui`; `flutter analyze` → "No issues found!"; `cargo clippy -- -D warnings`, `cargo fmt --check`.
- After changing `rust/src/api/`: `flutter_rust_bridge_codegen generate`; after changing the drift schema: `dart run build_runner build --delete-conflicting-outputs`; after changing fixtures: `dart run tool/embed_fixtures.dart`. Generated code is committed.
- Unit/widget tests never touch the network or Rust: transport, sources, tag writer, importer and download controller are injected via providers (`pumpApp` defaults to fakes).
- All YouTube client constants live in `lib/data/sources/youtube/innertube_clients.dart` and nowhere else.
- Never leave half files or rows: cancelled/failed jobs delete their temp folder; nothing reaches `library/` before the Importer.
- Every error reaches the UI as a short readable string (no logs on the iPhone).
- No requests on keystrokes; one download at a time.

## Review Focus

1. **A download breaks mid-file** (HTTP 403 on the second chunk, connection drop) → the job is `failed` with "Download failed: HTTP 403 after 10.0 of 24.0 MB", its temp folder is gone, no row. Test in Task 5.
2. **"Import Music" runs while a download reaches its import step** → the download waits, both end up in the library. Tests in Tasks 2 and 5.
3. **The same song queued twice** (double tap, or once from Songs and once from Videos: same `youtube:<id>`) → one job. Tests in Tasks 5 and 6.
4. **Titles that are not valid file names** ("AC/DC", "What?", 300 characters) → the temp file name is sanitized, the tags keep the exact text. Test in Task 5.
5. **The cover cannot be fetched or decoded** → the song is still added, without cover. Test in Task 5.

### Task 5: Download queue

**Files:** Create `lib/download/stream_download.dart`, `lib/download/download_job.dart`, `lib/download/download_controller.dart`; Modify `lib/app/providers.dart`, `lib/app/startup.dart`; Tests `test/download/stream_download_test.dart`, `test/download/download_controller_test.dart`, `test/app/startup_test.dart`; Fakes in `test/support/fakes.dart` (`FakeHttpTransport`, `FakeOnlineSource`, `FakeDownloadTagWriter`).

**Interfaces:** Consumes Tasks 1–4. Produces
```dart
class CancelToken { bool get isCancelled; void cancel(); }
class DownloadCancelled implements Exception {}
Future<void> downloadStream(HttpTransport http, ResolvedStream s, File target,
    {required void Function(int received, int total) onProgress, required CancelToken cancel, int chunkBytes = 10 << 20});
enum DownloadPhase { waiting, downloading, importing, done, duplicate, failed, cancelled }
class DownloadJob { int id; OnlineResult result; TrackTags tags; DownloadPhase phase; int received; int total; String? error;
  bool get isActive; /* waiting|downloading|importing */ DownloadJob copyWith(...); }
typedef WriteDownloadTags = Future<String?> Function(String path, TrackTags tags, ({Uint8List data, String mime})? cover);
class DownloadController extends Notifier<List<DownloadJob>> {
  void enqueue(OnlineResult result, TrackTags tags); // no-op if an active job has the same sourceKey
  void cancel(int id);    // waiting/downloading only
  void retry(int id);     // failed/cancelled → waiting, moved to the end
  void clearFinished();   // drops done, duplicate, failed, cancelled
}
final downloadControllerProvider = NotifierProvider<DownloadController, List<DownloadJob>>(DownloadController.new);
final downloadTagWriterProvider = Provider<WriteDownloadTags>(…Rust writeTags with CoverInput…);
final downloadDirProvider = Provider<Future<Directory> Function()>((ref) => () async => Directory(p.join((await getTemporaryDirectory()).path, 'download')));
Future<void> cleanupDownloads(Directory dir); // best effort, never throws
```
`downloadStream`: GET `url` + `&range=<start>-<end>` per chunk; append to `target`; a non-200 → `OnlineError('Download failed: HTTP <code> after <x.x> of <y.y> MB')`; a chunk that yields 0 bytes before the end → `OnlineError('Download stopped at <x.x> of <y.y> MB')`; fewer bytes than asked → continue from the new offset; `cancel` checked after every received block → cancel the subscription, throw `DownloadCancelled`.
Job run (one at a time, next starts when one ends): `resolve` → folder `<downloadDir>/<id>-<random>/` → `downloadStream` to `audio.part.m4a` (phase downloading, progress throttled to ≥1 % steps) → cover: GET `coverUrl` (failure or non-200 → no cover) → `Isolate.run(prepareCover)` → `WriteDownloadTags` (error → failed) → rename to `<sanitized "<artist> - <title>">.m4a` (replace `/\:*?"<>|` and control chars with `_`, trim, max 120 chars, empty artist → title only) → phase importing → `importerProvider.importFiles([path], sourceKeys: {path: result.sourceKey})` → added 1 → done; duplicates 1 → duplicate (`error` = "Already in your library"); else failed with `failures.first.reason` or "Could not be added". The job folder is deleted in every outcome. Any `OnlineError`/exception → failed with its message; `DownloadCancelled` → cancelled.
`startUp` gains `Future<Directory> Function()? downloadDir` and calls `cleanupDownloads` after `cleanupOrphans` (inside its own try: never fails startup).
