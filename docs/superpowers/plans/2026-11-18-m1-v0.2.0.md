# M1 / v0.2.0: Import, Database, Songs – Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Import audio files into an app-owned library (copy, read tags/cover via Rust, dedupe by hash), persist them in a drift database, show them in the Songs tab with delete, and add Settings (appearance + accent color) — released as `v0.2.0` and verified on the iPhone.

**Architecture:** Rust `read_track(path)` does all per-file work (tags, duration, BLAKE3 hash, cover bytes) on the FRB thread pool. Dart (`Importer`) copies files into `<ApplicationSupport>/library/`, writes rows through `TrackRepository` (drift), and Riverpod providers stream the library into the UI. The UI follows mockup v3 (`docs/mockups/m1-v3/`).

**Tech Stack:** Flutter 3.50.0, flutter_rust_bridge 2.13.0, lofty 0.25.5, blake3 1.8.x, drift 2.35 + drift_flutter 0.3 + drift_dev/build_runner, flutter_riverpod 3.5 (no codegen), file_picker 13.x, path_provider 2.1, package_info_plus 10.x, path 1.9.

**Spec:** `docs/superpowers/specs/2026-11-18-m1-import-library-design.md`

## Global Constraints

- Everything in the repo is English (code, comments, tests, UI strings, commits).
- Supported formats: MP3, M4A (MP4/AAC), AAC (ADTS), FLAC, WAV. Everything else is "not supported" and not copied. OGG is explicitly not supported.
- The DB stores **file names only** (`<hash>.<ext>`, `<coverhash>.<ext>`), never absolute paths — the iOS container path changes on app updates.
- Library root: `<getApplicationSupportDirectory()>/library/` with `audio/` and `covers/`.
- Duplicate key: BLAKE3 hex of the whole file.
- Title fallback: original file name without extension; artist fallback: `Unknown Artist`; no album tag → no album.
- Light mode = Paper (monochrome), dark mode = Midnight with accent; default appearance System, default accent Coral `#ff7a59`. Presets: Coral `ff7a59`, Amber `ffb340`, Lime `c6f432`, Teal `3ee0c4`, Sky `5ab4ff`, Violet `b38cff`, Pink `ff6fb5`.
- Imports `package:material_ui/material_ui.dart`, never `package:flutter/material.dart`. Icons from `CupertinoIcons`.
- Startup failures (Rust init, DB open) are shown on screen as selectable text (keep the M0 pattern).
- Generated code (FRB and drift `*.g.dart`) is committed; CI regenerates both and fails on any diff.
- v0.2.0 scope only: Songs tab (section headers, no A–Z index, no search, no sort menu), import, delete, settings. Albums/Artists tabs are placeholders. Play/Shuffle do not exist yet.

## Review Focus

1. **App update moves the iOS container** → library must still load: rows hold names only, paths are resolved against the current root. Test: Task 3 `TrackRepository` resolves files via `LibraryStorage`, schema has no path column.
2. **Corrupt or truncated file inside a batch** → reported in the summary, the rest of the batch still imports, nothing left on disk. Test: Task 2 `broken.mp3` → `Unreadable`; Task 5 batch with a broken file.
3. **Same file picked twice in one batch** → one added, one duplicate. Test: Task 5.
4. **Non-ASCII tags and file names** (umlauts, spaces) → stored and sorted sensibly; leading "The " and case ignored; "Ä" sorts under A. Test: Task 2 `unicode.mp3`, Task 4 sort keys.
5. **App killed mid-import** → no orphan `.part` files and no files without a row after next start. Test: Task 3 `cleanupOrphans`.

### Task 5: Importer

**Files:**
- Create: `lib/import/importer.dart`
- Test: `test/import/importer_test.dart`, `integration_test/import_test.dart`

**Interfaces:**
- Consumes: `readTrack` (Task 2), `TrackRepository`, `LibraryStorage` (Task 3), `displayArtist` (Task 4).
- Produces:
  - `typedef TrackReader = Future<ReadResult> Function(String path);`
  - `class ImportProgress { final int done; final int total; final String currentName; }`
  - `class ImportSummary { final int added; final int duplicates; final List<String> unsupported; final int albums; final int artists; int get checked; }` (`unsupported` holds original file names of unsupported **and** unreadable files; `albums`/`artists` = distinct counts among the added tracks; tracks without album do not count as an album)
  - `class Importer { Importer({required TrackRepository repo, required LibraryStorage storage, required TrackReader read}); Future<ImportSummary> importFiles(List<String> paths, {void Function(ImportProgress)? onProgress}); }`
- Per file, in order: extension not in `supportedFormats()` → unsupported (no copy); copy to `audio/<random>.part`; `read(partPath)`; status ≠ ok → delete part, unsupported; `repo.hasHash` → delete part, duplicate; write cover to `covers/<coverHash>.<ext>` if absent; rename part → `audio/<hash>.<ext>` (ext lowercased from the original); `repo.insert(...)` with `originalName`, `addedAt: DateTime.now()`. Any exception for one file → clean up that file's part/final file, count it as unsupported, continue. `onProgress` fires before each file and once at the end (`done == total`).
