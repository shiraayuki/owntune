# M3 v0.5.0 — Edit Info (fields, bulk, write back)

**Size:** project; first half of M3. The user asked to go ahead without a design discussion ("direkt los"), so every decision below is the builder's call, open to correction.

## Intent

Fix wrong or missing song information inside the app, for one song or a whole album / artist at once, so the library groups and shows songs correctly — and keep the files themselves in step, so the tags are right if a file ever leaves the app.

## Split of M3

- **v0.5.0 (this spec):** edit the text and number fields of one song, or of all songs of an album or an artist; write the changes into the file tags (lofty) and the database.
- **v0.5.1:** covers (pick from photos/files, crop square, remove; written into the tags too) and multi-select in the Songs list for bulk editing.

## Goals

- **Fields:** Title, Artist, Album, Album Artist, Genre, Track, Disc, Year. Numbers accept digits only (Track/Disc up to 3 digits, Year 4); an empty field clears the value.
- **Edit Info screen:** full-screen page (slides up, `fullscreenDialog`) with "Cancel" left, the title "Edit Info" in the middle and "Save" right (accent, bold; disabled until something changed and while saving). Fields as an iOS inset-grouped form: label left, value right-aligned.
- **One song:** "Edit Info" in the song menu (every list, and in Now Playing).
- **Bulk:** a "…" button on the album and artist pages' top row opens a menu with "Edit Info" for all their songs. In bulk, Title and Track are not shown; a field whose value differs between the songs shows the placeholder "Mixed" and stays as it is per song unless typed into. A field is changed when its text differs from what it showed at the start.
- **Write back:** per song, the file is written first, then the row. The file is written safely: copy to `audio/<name>.part.<ext>`, write the tags there, rename over the original (an interrupted write leaves the original intact; `cleanupOrphans()` removes the leftover). Tags written into the file's primary tag (ID3v2 for MP3/WAV/AAC, MP4 for M4A, Vorbis comments for FLAC), created if missing; a cleared field removes the item.
- **Bulk updates land at once:** all rows of one save are updated in one transaction, so lists and detail pages change in one step.
- **Detail pages follow their songs:** an album page whose album was renamed (title or album artist) shows the renamed album; an artist page whose artist was renamed shows the renamed artist. They still close when their last song is deleted.
- **Errors visible:** songs that could not be saved are listed in a dialog ("Couldn't save 2 songs" + names + reason); the others are saved.
- **Duplicates:** the stored content hash stays the hash at import, so importing the original file again is still detected as a duplicate. The file name (`<hash>.<ext>`) stays.

## Non-goals

Covers and multi-select (v0.5.1); editing comments, lyrics, composer, BPM, track/disc totals; undo; renaming files; editing several albums at once.

## Anti-goals

- A failed write that corrupts or loses an audio file.
- Database and file drifting apart silently (a failed file write must not update the row).

## Approaches

1. **Rust writes, Dart orchestrates** (picked). `write_tags(path, tags)` in Rust (lofty, already used for reading) writes one file atomically and returns an error message or none; Dart computes the final tags per song, calls it, then updates the rows. Testable like the importer (the writer function is injected).
2. **Dart tag library for writing.** A second tag implementation next to lofty, weaker format coverage; ruled out in M1 already.
3. **Write tags lazily (DB first, files later in the background).** Simpler UI, but DB and files drift apart and failures surface late; contradicts "write back".

## Left to the builder

Exact widget structure, Rust struct names, provider shape, test split. Tests: Rust round-trip per format (write, read back, cleared fields gone, other tags kept, file still plays/has same duration); Dart unit tests for the edit model (mixed values, clear vs. keep) and the saver (file then row, failures, one transaction); widget tests for the screen (single and bulk, Save state, number fields), the menu entries, and detail pages following a rename; an integration test that edits a fixture copy with the real Rust core.
