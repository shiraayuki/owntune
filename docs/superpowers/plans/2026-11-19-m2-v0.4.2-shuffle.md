# M2 v0.4.2 Shuffle Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Spotify-like spread shuffle (toggle in Now Playing, Shuffle on album/artist pages, saved across restarts) and Now Playing's top row below the status bar.

**Architecture:** A pure `spread()` orders items so songs by the same artist (and, within an artist, the same album) are spread out. `PlayQueue` reorders its own entries when shuffled and keeps the original order aside (`original`), so Up Next, Previous, system controls and restore keep following `entries`. The controller passes a spread function built from the library and an injectable `Random`; the snapshot stores the original order as positions.

**Tech Stack:** Flutter 3.50, flutter_riverpod 3, `dart:math` `Random`.

**Spec:** `docs/superpowers/specs/2026-11-19-m2-v0.4.2-shuffle-design.md`

## Global Constraints

- Everything in English; `package:material_ui` / `package:cupertino_ui` imports; `flutter analyze` → "No issues found!".
- With shuffle off, every existing behaviour (queue, Up Next, repeat, restore, system controls) is unchanged — all existing tests stay green unchanged, except the three "Shuffle is disabled" tests, which are replaced.
- Randomness only through `randomProvider` (tests override it with `Random(seed)`).
- Artist key: `artistGroupKey(track.artist)`; album key: `albumKeyOf(track)` (both in `lib/library/library.dart`).
- No lock-screen shuffle button, no Smart Shuffle.

## Review Focus

1. **Turning shuffle off after Play Next / Up Next edits** — Play Next songs stay right after the current song, removed songs do not come back. Tests in Task 3.
2. **Same track queued twice** — both entries survive shuffle on/off (entries are matched by key, never by track id). Test in Task 3.
3. **Songs deleted while shuffled** — they leave both orders; turning shuffle off afterwards does not bring them back or crash. Test in Task 3.
4. **Old saved state (v0.4.1 JSON without `shuffleOrder`) and broken `shuffleOrder`** — restores with shuffle off / is ignored, never a crash. Test in Task 4.
5. **Queue emptied while shuffle is on** (all songs deleted, then a new song tapped) — the new queue is shuffled, because the mode is sticky. Test in Task 4.

### Task 2: Spread order

**Files:** Create `lib/player/shuffle.dart`; Test `test/player/shuffle_test.dart`

**Interfaces:** Produces
```dart
/// Orders [items] so items with the same [artist] are spread evenly, and
/// within an artist the same [album]; random offsets keep it irregular.
List<T> spread<T>(
  List<T> items, {
  required Object? Function(T) artist,
  required Object? Function(T) album,
  required Random random,
});
```
Algorithm (not determined by the tests, use this):
```dart
List<T> level(List<T> xs, List<Object? Function(T)> keys) {
  if (xs.length < 2) return [...xs];
  if (keys.isEmpty) return [...xs]..shuffle(random);
  final groups = <Object?, List<T>>{};
  for (final x in xs) (groups[keys.first(x)] ??= []).add(x);
  final placed = <(double, T)>[];
  for (final g in groups.values) {
    final ordered = level(g, keys.sublist(1));
    final n = ordered.length;
    final offset = random.nextDouble() / n;
    for (final (i, x) in ordered.indexed) {
      final jitter = (random.nextDouble() - 0.5) * 0.1 / n;
      placed.add((offset + i / n + jitter, x));
    }
  }
  placed.sort((a, b) => a.$1.compareTo(b.$1));
  return [for (final p in placed) p.$2];
}
return level(items, [artist, album]);
```

Tests use records `(int id, String artist, String album)`; `neighbours(order, key)` counts adjacent pairs with equal key.
- [ ] Failing tests: `keeps every item exactly once` (12 items, sorted result equals sorted input); `spreads artists` (3 artists × 4 songs, one album each; over seeds 0..199 the summed same-artist neighbours ≤ 20 — a plain shuffle gives ~600); `spreads albums within one artist` (1 artist, 2 albums × 4; summed same-album neighbours over seeds 0..199 ≤ 60 — a plain shuffle gives ~600; a simulation of the algorithm gave 20); `differs between seeds` (seeds 1 and 2 give different orders of 12 items); `same seed, same order`; `zero and one item` (returned unchanged).

### Task 3: Shuffled queue

**Files:** Modify `lib/player/play_queue.dart`; Test `test/player/play_queue_test.dart`

**Interfaces:** Consumes nothing from Task 2 directly. Produces on `PlayQueue`:
```dart
typedef Spread = List<QueueEntry> Function(List<QueueEntry> entries);

const PlayQueue({..., this.original});        // null = shuffle off
final List<QueueEntry>? original;             // the unshuffled order while shuffled
bool get shuffled => original != null;
factory PlayQueue.of(List<int> trackIds, {required int start, String? source,
    QueueRepeat repeat = QueueRepeat.off, List<int>? originalOrder});
    // originalOrder: positions into trackIds giving the unshuffled order (from the snapshot)
PlayQueue shuffleOn(Spread spread, {bool keepCurrent = true});
    // keepCurrent: entries = [current, ...spread(all others)], index 0;
    // otherwise entries = spread(all), index 0. original = the entries before (or the existing original if already shuffled).
PlayQueue shuffleOff();   // entries = original, index = position of the current key in it, original = null
PlayQueue? following({required bool auto, required Spread spread});
    // the queue after the current song, null = stop. Same as withIndex(nextIndex(auto:)),
    // except shuffled + repeat all + wrapping from the last entry with >1 entries:
    // entries = spread(entries); if its first is the current entry, swap the first two; index 0.
```
Rules: `insertNext`/`append` also insert into `original` (right after the current key's position / at the end). `remove`, `clearUpcoming`, `retain` keep `original` filtered to keys still in `entries`. `moveUpcoming`, `withRepeat`, `withIndex`, `jumpTo` keep `original` as is. `_copy`/`_withNew` carry `original`. An empty shuffled queue is `PlayQueue(original: const [])`.

Tests use `Spread reverse = (es) => es.reversed.toList();` so orders are predictable.
- [ ] Failing tests: `shuffle on keeps the current song first` (of [1,2,3,4] start 1, `shuffleOn(reverse)` → ids [2,4,3,1], index 0, `shuffled`); `shuffle on without keepCurrent spreads all` (→ [4,3,2,1]); `shuffle off continues in the original order` (then `withIndex(2)` (track 3), `shuffleOff()` → ids [1,2,3,4], index 2, `!shuffled`); `Play Next while shuffled stays after the current song in both orders` (shuffled at track 2, `insertNext(9)`, `shuffleOff()` → [1,2,9,3,4], index 1); `Play Later lands at the end of both orders`; `a removed song stays gone after shuffle off`; `clear Up Next while shuffled` (shuffled at track 2, `clearUpcoming()`, `shuffleOff()` → [2], index 0); `retain drops deleted songs from both orders`; `the same track twice survives shuffle on and off` (of [1,1,2] → shuffleOn → shuffleOff → ids [1,1,2], keys unchanged); `following wraps with a new order under repeat all` (shuffled, repeat all, at last entry; `following(auto: true, spread: reverse)` → index 0 and first entry ≠ the entry that ended); `following stops at the end with repeat off`; `following repeats one`; `of with originalOrder restores the unshuffled order` (of [3,1,2] originalOrder [1,2,0] → `original` ids [1,2,3]); `an empty shuffled queue stays shuffled`.

### Task 4: Controller, saved state

**Files:** Modify `lib/player/player_controller.dart`, `lib/player/player_snapshot.dart`, `test/support/fakes.dart` (if a seeded `randomProvider` override helps `pumpApp`); Test `test/player/player_controller_test.dart`, `test/player/player_snapshot_test.dart`, `test/player/player_restore_test.dart`

**Interfaces:** Consumes `spread` (Task 2), `PlayQueue` shuffle API (Task 3). Produces:
```dart
final randomProvider = Provider<Random>((ref) => Random());   // in player_controller.dart
Future<void> playList(List<Track> tracks, {required int start, required String source, bool? shuffle});
    // null keeps the current mode (tapped song first when on); true → shuffle on, start ignored,
    // shuffleOn(keepCurrent: false); false → shuffle off
void toggleShuffle();        // shuffleOn(keepCurrent: true) / shuffleOff(); playback continues uninterrupted
PlayerSnapshot({..., this.shuffleOrder});    // List<int>? positions into trackIds, JSON key 'shuffleOrder'
```
The controller's spread function maps entries through `_tracks` (`artistGroupKey(t.artist)`, `albumKeyOf(t)`; a missing track → key null) with `ref.read(randomProvider)`. `next()`, `_onCompleted()` and `_onFailure()` use `following(...)` instead of `withIndex(nextIndex(...))`. `_stop()` keeps the mode: `PlayQueue(repeat: …, original: _queue.shuffled ? const [] : null)`; so does `_add` on an empty queue. Saving: the snapshot includes `shuffleOrder` (positions of `original`'s keys in `entries`) when shuffled; `_saveQueueIfChanged` also saves when `shuffled` or `original` changed. `tryParse`: a `shuffleOrder` that is not a permutation of `0..trackIds.length-1` → the whole snapshot is still used, with `shuffleOrder` null. Restore passes `originalOrder: saved.shuffleOrder`.
