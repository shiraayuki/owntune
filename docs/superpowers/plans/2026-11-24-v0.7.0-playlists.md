# v0.7.0 Playlists Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Real playlists (create, add, play, reorder, rename, cover, delete) plus a Spotify-style "…" button on every song row.

**Architecture:** Two drift tables (`playlists`, `playlist_entries`) behind a `PlaylistRepository`; a stream provider of raw rows is resolved in Dart against `tracksProvider` into `PlaylistView`s (entries whose track is gone are dropped), the same way albums/artists are derived. UI lives in `lib/playlists/`; it reuses `SongRow`, `PlayShuffleButtons`, `NavRow`, `showCoverMenu`, the crop page and the isolate cover functions.

**Tech Stack:** Flutter 3.50 / Dart 3.14, drift, flutter_riverpod 3 (no codegen).

**Spec:** `docs/superpowers/specs/2026-11-24-v0.7.0-playlists-design.md` — read it first; this plan only adds the how.

## Global Constraints

- Everything in English (code, comments, UI strings, commits).
- Import `package:material_ui/material_ui.dart` and `package:cupertino_ui/cupertino_ui.dart` (`CupertinoIcons`), never `package:flutter/material.dart` / `cupertino.dart`.
- `flutter analyze` must report "No issues found!"; `flutter test` green after every task.
- The DB stores file names only, never paths. Covers are `covers/<blake3>.jpg`, written via `LibraryStorage.storeCover`.
- After schema changes: `dart run build_runner build --delete-conflicting-outputs`; commit `database.g.dart`.
- Errors visible in the UI (dialogs with `SelectableText`), never only logged.
- Commit after each task; message style `feat: …` / `fix: …` / `docs: …`, ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **A cover shared by a track and a playlist** (same image hash): deleting the track, editing the track's cover, or startup cleanup must not delete it; replacing/removing the playlist cover must not delete it while a track uses it. → tests in Task 1.
2. **The same song twice in a playlist**: Remove from Playlist removes only that entry; tapping the second copy starts playback at the second position. → tests in Tasks 1 and 4.
3. **A song deleted from the library** while it is in playlists (also while Edit Playlist is open): entries vanish, counts/durations/mosaic update, Done doesn't fail. → tests in Tasks 1, 2, 5.
4. **Playlist deleted while its detail page is open** (or from that page): the page pops itself, no red screen. → test in Task 4.
5. **Empty/whitespace names**: Create and Done stay disabled; names are stored trimmed. → tests in Tasks 3 and 5.

**Interfaces:**
- Produces (drift): tables `Playlists` (`id` autoinc, `name` text, `coverFile` text nullable, `createdAt` dateTime) and `PlaylistEntries` (`id` autoinc, `playlistId` int `references(Playlists, #id)`, `trackId` int `references(Tracks, #id)`, `position` int), `@TableIndex(name: 'playlist_entries_order', columns: {#playlistId, #position})`. Generated row classes `Playlist`, `PlaylistEntry`. Do **not** turn on `PRAGMA foreign_keys`; delete entries explicitly.
- Produces:
  ```dart
  class PlaylistRepository {
    PlaylistRepository(AppDatabase db, LibraryStorage storage, {required String Function(Uint8List) hash});
    Stream<List<Playlist>> watchPlaylists();          // all rows
    Stream<List<PlaylistEntry>> watchEntries();       // all rows, any order
    Future<int> create(String name, {Uint8List? cover}); // trims name; returns id; createdAt = now
    Future<void> addTracks(int playlistId, List<int> trackIds); // appends at the end, keeps order and duplicates
    Future<void> removeEntry(int entryId);            // renumbers the rest densely 0..n-1
    Future<void> saveEdit(int playlistId, {required String name, required List<int> entryIds, required PlaylistCoverChange cover});
    Future<void> delete(int playlistId);              // entries + row; then its cover file if unreferenced
  }
  sealed class PlaylistCoverChange {}  // PlaylistCoverKeep, PlaylistCoverSet(Uint8List jpeg), PlaylistCoverRemove
  ```
  `saveEdit` runs in one transaction: sets the trimmed name, deletes entries of this playlist not in `entryIds`, writes `position = index in entryIds` for the rest (ids that no longer exist are ignored), sets/clears `coverFile`. A `PlaylistCoverSet` is stored first via `storage.storeCover('${hash(jpeg)}.jpg', jpeg)`; after the transaction the old cover file is deleted if `TrackRepository.isCoverReferenced`-style check (tracks **and** playlists) says it is unused. `create` with a cover stores it the same way.
- Produces (TrackRepository changes): `delete(id)` also deletes `playlist_entries` with that `trackId` and renumbers affected playlists; `isCoverReferenced(name)` is true if any track **or playlist** has `coverFile == name`; `cleanupOrphans()` keeps track covers ∪ playlist covers. Put the shared "is referenced" query where both repositories can call it (e.g. a top-level `Future<bool> isCoverInUse(AppDatabase db, String name)` in `track_repository.dart`).

- [ ] **Step 1: Write failing tests** in `test/data/playlist_repository_test.dart` (in-memory DB + temp `LibraryStorage`, pattern of `track_repository_test.dart`; `hash: (b) => 'h${b.length}'`):

  - `addTracks appends in order and keeps duplicates` → add `[1,2]` then `[1]` → entries by position have trackIds `[1,2,1]`, positions `[0,1,2]`.
  - `removeEntry removes one copy and renumbers` → from `[1,2,1]` remove the last entry → `[1,2]`, positions `[0,1]`; the other copy of track 1 stays.
  - `saveEdit reorders, drops missing entries, renames` → entries `[a,b,c]`, `saveEdit(entryIds: [c, a, 999])` → order `[c,a]`, b deleted, 999 ignored.
  - `saveEdit with a new cover stores it and deletes the unused old one`, and `… keeps the old cover file when a track still uses it`.
  - `delete removes entries, row and unused cover`.
