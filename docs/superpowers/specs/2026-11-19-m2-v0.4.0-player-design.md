# M2 v0.4.0 — Player (design)

**Size:** project. **Mockups:** `docs/mockups/m2-v1/` — mini player (02, 04, 07, 08), song menu (08), Now Playing (09), Up Next (10). M2 is released in two parts: **v0.4.0** (this document) plays music inside the app; **v0.4.1** adds background playback, lock screen / Control Center, and restoring the player after a restart.

## Intent

owntune can import and browse a library but cannot play it yet. v0.4.0 makes it a music player you can use while the app is open: tap a song and it plays, with the list it came from as the queue, a mini player on every screen, a full-screen player and an editable Up Next list. It is built so that v0.4.1 can put `audio_service` in front of it without rewriting the playback logic.

## Goals

- **Tap to play.** Tapping a song row plays it; the list it was tapped in becomes the queue, in the order shown (including the current sort and any active search filter). This applies to every song list: Library › Songs, album detail, artist detail (its song preview), artist songs ("See All"), and the songs in Search.
- **Play on album and artist pages.** "Play" plays the album from its first track (disc/track order), or all of the artist's songs in the order of the artist songs screen.
- **Mini player** (mockup `.mini`): floats above the tab bar on every tab, and at the bottom of pushed screens (album, artist, artist songs) where there is no tab bar (`.mini.no-tabs`). Shows cover, title, artist, a play/pause button, a next button and a thin progress line in the accent colour. Tapping it (outside the buttons) opens the player. Hidden while nothing is loaded. Lists get enough bottom padding that their last row can scroll above it.
- **Now Playing** (mockup 09): opens as a full-screen sheet sliding up, closes by swiping down or tapping the grabber. Blurred copy of the cover as the background, large cover, title, `artist · album`, a "…" button, scrubber with elapsed and `-remaining` time, controls (shuffle, previous, play/pause, next, repeat) and an "Up Next" pill.
- **Up Next** (mockup 10): the pill swaps the large cover for the queue view: a compact now-playing row, the header "Up Next" with "Clear", the line "Playing from <source>", and the upcoming songs. Drag the grip to reorder, swipe left to remove, "Clear" removes all upcoming songs (the current song keeps playing). The scrubber and controls stay docked at the bottom. Tapping a row in Up Next jumps to that song.
- **Song menu** (mockup 08): "Play Next" and "Play Later" are added above the existing entries. Play Next inserts the song directly after the current one; Play Later appends it to the end of the queue.
- **Repeat** cycles off → all → one; the button shows the state (`repeat`, tinted `repeat`, tinted `repeat-1`).
- **Now-playing highlight in lists:** the current song's title is tinted in song rows; in the album track list its number is replaced by the bars glyph (mockup 07, `.row.playing`).
- **Errors stay visible:** a song that cannot be played (missing file, decoder error) is skipped and a short non-blocking notice names it ("Couldn't play “<title>”"). There are no logs on the iPhone.

## Non-goals (v0.4.0)

- **Shuffle.** The shuffle toggle in the player and the "Shuffle" buttons on album/artist pages are shown **disabled** (like the "New Playlist" placeholder). No shuffle logic.
- Background playback, `UIBackgroundModes: audio`, lock screen and Control Center, headphone/remote buttons, `audio_service` → v0.4.1.
- Restoring queue, position and repeat after a restart → v0.4.1.
- Gapless playback, crossfade, playback speed, equalizer.
- Volume slider and AirPlay / output picker (not in the mockups; hardware buttons and system controls handle volume).
- A separate "added by you" section in Up Next (Apple Music style). Up Next is one list.

## Anti-goals

- Playback logic that lives inside the audio plugin and can only be tested with real audio.
- The queue drifting out of sync with the library: a deleted song must never stay in the queue or keep playing from a deleted file.
- The app crashing or silently stopping when a file cannot be played.

## Constraints

- Development and tests run on Linux without a Mac; iOS is built only in CI. Unit and widget tests must run without native audio.
- Packages: `just_audio` (iOS, Android) and `just_audio_media_kit` (+ `media_kit_libs_linux`) on Linux. libmpv is installed on the dev machine; CI's Linux job needs `libmpv-dev` added to its apt packages, because the integration tests build the Linux app.
- `audio_session` is configured for music (iOS category `playback`), so the ring/silent switch does not mute playback. This is a session setting only; without `UIBackgroundModes` the app still stops when it leaves the foreground, which is accepted for v0.4.0.
- Paths: tracks are played from `LibraryStorage.audioFile(track.fileName)`; nothing new is stored as a path.
- Package versions are pinned as for existing dependencies; check that the chosen `just_audio_media_kit` works with the pinned Flutter 3.50.

## Approaches

1. **Own queue in Dart, the plugin plays one file at a time** (chosen). A `PlayerController` (Riverpod notifier) owns the queue, the current index, the repeat mode and the playing/paused state, and decides what comes next. It talks to the plugin through a small `AudioEngine` interface (load file, play, pause, seek, position/duration/completed/error streams); tests use a fake engine. The whole queue logic is testable on Linux, and in v0.4.1 `audio_service` sits in front of the controller. Trade-off: a short gap (milliseconds) between songs, no gapless playback.
2. Queue inside the plugin as a just_audio playlist source. Gapless and a bit less code, but the order lives in the plugin, the UI has to mirror it, reordering/removal goes through the plugin API, it is hard to test without real audio, the media_kit backend behaves differently from iOS/Android for playlists, and v0.4.1 would have to sync audio_service with the plugin. Rejected.
3. `audio_service` already in v0.4.0. That is v0.4.1's work and was explicitly postponed.

## Playback rules

These are my calls where the mockups do not say; please check.

- **Previous:** more than 3 s into the song → restart it; otherwise go to the previous song. On the first song it restarts it.
- **Next:** goes to the next song; with repeat all, from the last song to the first. With repeat off on the last song, it does nothing (button disabled).
- **Repeat one** only applies when a song ends by itself; Next/Previous still move through the queue.
- **End of the queue** (repeat off): playback stops on the last song, which stays loaded, paused at 0:00. The mini player stays.
- **Play Next / Play Later with nothing loaded:** the song becomes a one-song queue and starts playing; Up Next then shows no "Playing from" line.
- **Duplicates are allowed:** Play Next/Later of a song that is already queued adds another entry. Queue entries therefore have their own identity (not just the track id), so reordering and removing act on the right row.
- **Artist page preview:** tapping one of the few songs shown on the artist page queues *all* of the artist's songs (in artist-songs order) and starts at the tapped one, rather than queueing only the preview.
- **Tapping the song that is already current** in a list restarts the queue from that list anyway (the list may have a different order than the current queue).
- **Deleting a song** (song menu or a later import rollback) removes it from the queue. If it is the current song, playback moves to the next song and keeps its play/pause state; if the queue becomes empty, the player unloads and the mini player disappears.
- **Library changes** (import, tag changes later) update the queue entries' displayed data, because the controller stores track ids and reads the current `Track` from the library snapshot.
- **"Playing from" source label:** the album title, the artist name, "Songs", or "Search".
- **Play count:** when a song plays to its end, `playCount` is incremented and `lastPlayedAt` set (columns exist already; nothing collected now can be recovered later for M5 statistics). Skipped songs do not count.
- **The player's "…" button** opens the song menu for the current song (Play Next/Later left out; Go to Album / Go to Artist close the player first and push the screen; Delete from Library as in lists).
- **Scrubbing** seeks on release; the time labels follow the finger while dragging.
- **Unplayable song:** skip to the next song and show the notice; if every song in the queue fails in a row, stop and unload.
- **Audio setup** (media_kit initialisation on Linux, `audio_session` configuration) runs in `startUp()`, injected like the other native calls; a failure there becomes `StartupFailed`, consistent with the existing startup pattern.

## Left to the builder

File and widget layout (e.g. `lib/player/`), the exact `AudioEngine` API, how the mini player reaches pushed screens (it must sit above the navigator, like the import sheets via `MaterialApp.builder`, and know whether a tab bar is visible), the sheet animation, the notice widget, provider shape and test split. Tests: controller unit tests with a fake engine for every rule above; widget tests for tap-to-play from each list, mini player visibility and buttons, player open/close, Up Next reorder/remove/clear, song-menu entries, disabled shuffle, now-playing highlight; one integration test on Linux that plays a fixture through the real engine and sees position advance and completion. CLAUDE.md is updated (status, packages in use, `lib/player/` in the architecture), version `0.4.0`.

**Addendum (implementation):** the mini player sits in each Scaffold's bottom bar (app shell above the tab bar; album, artist and artist-songs screens on their own), not above the navigator, so popup menus and dialogs dim it with the rest of the screen and `extendBody` gives lists their bottom padding (plan Task 6). The repeat enum is called `QueueRepeat`, because Flutter's widgets library exports a `RepeatMode`.
