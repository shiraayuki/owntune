# M1 v0.3.0: Albums, Artists, Search, Sort – Design

Date: 2026-11-19 · Parent spec: `2026-11-18-m1-import-library-design.md` (all of its goals, rules and decisions still apply) · UI reference: `docs/mockups/m1-v3/` screens 04–10 and 12 · Branch: `m1-v0.3.0`

## Intent

v0.2.0 proved the risky part on the iPhone: import, database and the Songs list. v0.3.0 finishes M1 by making the library browsable the way the mockup shows: albums, artists, their detail screens, a global search, sorting and the A–Z index for Songs. After v0.3.0 the M1 "done when" criterion of the parent spec can be checked on the iPhone (50 mixed files imported, grouped and sorted correctly, a song deleted, all of it still there after a restart).

Nothing about how files and tags are stored changes. v0.3.0 is a pure read/browse layer on top of the v0.2.0 `tracks` table, plus one stored setting (the Songs sort order).

## Goals

1. **Albums tab** (mockup 06): 2-column grid of albums, square cover (radius 10), title and album artist below. Sorted by album artist, then album title (both with `sortKey`).
2. **Album detail** (mockup 07): large cover (270pt), title, album artist, `genre · year` line (each part omitted if unknown, the line omitted if both are), disabled Play/Shuffle, then the tracks ordered by disc number, track number, title. Each row: track number (blank if missing), title, duration `m:ss`; if the track's artist differs from the album artist (case-insensitive), the track artist is shown as a second line (the mockup's "feat. Mira Sol" is just the track artist). If the album has more than one disc number, a small "Disc N" header precedes each disc.
3. **Artists tab** (mockup 08): list of artists, 48pt round avatar, name, `N albums · M songs` (the albums part omitted when 0; singular "1 album"/"1 song"), chevron. Sorted by `sortKey`.
4. **Artist detail** (mockup 09): 150pt round avatar, name, `N albums · M songs`, disabled Play/Shuffle; an "Albums" section with a horizontal row of 150pt album cards (cover, title, year) — omitted if the artist has no albums; a "Songs" section with the first 5 of the artist's songs (sorted by title, rows like the Songs tab but the subtitle is only the album), and a "See All" link when there are more than 5. "See All" opens a plain list of all the artist's songs, titled with the artist's name.
5. **Search** (mockup 10): every tab shows a search field below the title row ("Search Songs" / "Search Albums" / "Search Artists"). Tapping it opens one global search screen (same for every tab): a focused text field with a clear button and "Cancel". Results update while typing, grouped in this order: Artists (subtitle "Artist"), Albums ("Album · <album artist>"), Songs ("Song · <artist>"). Empty query shows nothing; a query without matches shows `No results for "<query>"`. Tapping an artist or album opens its detail screen on top of the search; "Cancel" closes the search.
6. **Songs sorting** (mockup 05): the "…" menu on the Songs tab gets a "Sort By" section (Title, Artist, Album, Recently Added, the active one checked) and an Ascending/Descending section (active one checked), then Settings. A line below the search field shows `N songs · sorted by <title|artist|album|recently added>`. The choice is stored and survives a restart. On the Albums and Artists tabs the "…" menu keeps only Settings.
7. **A–Z index** on the Songs tab (mockup 04): a vertical strip of `A`–`Z` and `#` at the right edge. Tapping or dragging over it jumps the list to the section of that letter (or the next section after it if the letter has no songs). If the strip has less height than all 27 letters need, letters are collapsed with `•` as in the mockup. The index is shown only when the list has section headers (see Sorting rules).
8. **Song context menu** (mockup 12): "Go to Album" and "Go to Artist" above "Delete from Library". "Go to Album" is omitted for a track without album; "Go to Artist" opens the track's artist (also "Unknown Artist"). On a detail screen, the entry that would open the screen itself is omitted. The menu works on every song row: Songs tab, album detail, artist detail, "See All" list, search results.
9. **Release:** version `0.3.0` in `pubspec.yaml`, `CLAUDE.md` status updated, tag `v0.3.0` after the user has checked the build.

## Non-goals

- Playback of any kind. Play/Shuffle are visible but disabled; tapping a song row does nothing in v0.3.0 (M2 will play it).
- Actions on albums or artists (no long-press menu on album cards or artist rows, no "…" button on detail screens — the mockup's detail "…" has nothing to hold before M3).
- Artist images. Avatars are derived from covers (see Derived data).
- Splitting "feat." credits, "Various Artists" handling beyond what the album identity rule gives.
- Search history, fuzzy matching, searching inside genres or years.
- Any change to import, storage, the Rust core or the drift schema version (the sort setting goes into the existing key/value table).

## Anti-goals

- A detail screen that keeps showing an album or artist that no longer exists (after a delete) or that shows stale data while an import runs.
- Grouping that differs between the Albums tab, the artist's albums row, search and "Go to Album" — all must come from one derivation.
- A UI that stutters while an import adds tracks (the library is re-derived on every change).

## Constraints

- Everything in `CLAUDE.md` and the parent spec. In particular: UI follows mockup v3 (light Paper / dark Midnight with accent), repo and UI language English, no new packages unless unavoidable, logic testable on Linux without the native library.
- Back navigation must work with the iOS edge-swipe gesture (a page route with Cupertino transitions on iOS).

## Approaches

**How albums and artists are derived** (my call, accepted by the user)
- **A – In memory, in Dart:** one provider turns the existing `watchAll()` track stream into a `Library` snapshot (sorted songs, albums, artists, lookup maps). Tabs, detail screens, search and "Go to …" all read from it. Reuses `sortKey`/`displayArtist`, trivially unit-testable, one source of truth. Re-deriving a few thousand tracks on each change is well within budget. **Chosen.**
- B – SQL `GROUP BY` queries per view: scales further, but the grouping and sorting rules (leading "The", diacritic folding, album artist fallback, most common year) are not expressible in SQLite without custom functions, and four separate queries can disagree mid-import.
- C – Album/artist tables kept in sync on import and delete: what M4 (custom albums) may eventually need, but premature now; adds a migration and a class of sync bugs for no v0.3.0 benefit.

**Navigation** (my call, follows the mockup): detail screens, "See All" and search are pushed on the app's root navigator, above the tab shell, so the tab bar is hidden there (mockups 07, 09, 10 have none). Not chosen: nested per-tab navigators (iOS-Music style, tab bar stays) — the mockup shows otherwise, and it complicates "Go to Album" from search.

## Derived data (the rules)

All keys below are `trim().toLowerCase()` unless stated; `sortKey` is the existing function in `lib/library/sort_key.dart`.

- **Album identity:** (album artist key, album title key), where album artist = `albumArtist`, falling back to `artist`, falling back to "Unknown Artist". Tracks with a blank album tag belong to no album. (Unchanged from the parent spec; note that grouping uses plain lowercase, not `sortKey`, so "The Band" and "Band" stay apart.)
- **Album display values:** title and album artist as spelled on its first track (by disc, track, title); year = the most common non-null year among its tracks (ties: the later year); genre = the most common non-blank genre (ties: alphabetical first); cover = the cover of the first track that has one.
- **Artist identity:** key of the track `artist`; blank/missing → the "Unknown Artist" group. Display name as spelled on the first track (by title sort). An artist exists only if at least one track has it as track artist.
- **An artist's songs:** tracks whose track artist key equals the artist key.
- **An artist's albums:** albums whose album artist key equals the artist key (so an artist who only appears on a compilation shows songs but no albums, matching mockup 08's "Lumen Kids · 1 song"). Ordered by year descending, unknown year last, then title.
- **Artist avatar:** the cover of the artist's newest album that has one, else the cover of any of their songs, else a placeholder circle with a person icon.
- **Search matching:** the query and each candidate string are normalised the way `sortKey` normalises (lowercase, diacritics folded) but without stripping a leading "the"; a candidate matches if it contains the trimmed query. Artists match on name; albums on title or album artist; songs on title, artist or album. Each group is ordered by `sortKey` of its display name.

## Sorting rules (Songs tab)

Default: Title, Ascending (as v0.2.0).

| Sort | Ascending order | Section letter / index |
|---|---|---|
| Title | title, then artist | first letter of the title |
| Artist | artist, then album, then disc, track, title | first letter of the artist |
| Album | album, then album artist, then disc, track, title (tracks without album last) | first letter of the album, `#` for none |
| Recently Added | newest first | none, and no index |

All comparisons use `sortKey`, with one change from v0.2.0: everything whose section letter is `#` (digits, symbols, non-Latin, no album) sorts **after Z** in ascending order, as in iOS Music, so there is only ever one `#` section and it matches the index strip's position. Descending reverses the whole list (Recently Added descending = oldest first). Section headers appear wherever the letter changes, so in descending order they run Z→A; the index strip always shows A–Z, # and jumps to wherever that letter's section is. If the tapped letter has no section, it jumps to the section of the next letter in the alphabet that has one (A→Z→#), regardless of direction. The row subtitle stays `artist · album` for every sort.

Stored in `settings_entries` as `songs_sort` (`title|artist|album|added`) and `songs_sort_desc` (`true|false`), loaded at startup with the other settings; unknown values fall back to the default.

## Screen behavior details

- **Import sheets above everything:** today `ImportOverlay` lives in `AppShell`'s Stack, below the root navigator, so a summary or failure sheet would stay hidden behind a pushed detail or search screen — violating the "errors visible in the UI" rule. The overlay moves above the navigator (`MaterialApp.builder`), so import progress, summary and failure sheets show over any screen. Existing widget tests are adjusted accordingly.
- **Back button** on pushed screens: chevron plus the title of the screen underneath ("Albums", "Artists", "Songs", an artist's name, or "Search").
- **Live updates:** detail screens hold an album/artist key, not a snapshot, and re-resolve it from the live `Library` on every change. If the key no longer resolves (last track deleted), the screen pops itself.
- **Empty states:** with an empty library, all three tabs show the existing empty state (record graphic and Import Music). If there are tracks but no albums, the Albums tab shows a short centered "No albums – songs without an album tag appear under Songs and Artists." text.
- **Search field on the tabs** is a tappable look-alike (not a real text field); it sits between the title row and the list and does not scroll away.
- **Play/Shuffle** reuse `PillButton(secondary: true, onPressed: null)`.

## Decisions

By the user:
- Everything in the parent spec (formats, copy, mockup v3, release split).
- Approach A (in-memory derivation), the screen and behavior calls listed in the 2026-11-19 conversation: sort applies to Songs only and is stored; Recently Added has no sections or index; detail screens hide the tab bar; no "…" on detail screens yet; search is substring, case- and accent-insensitive.

My calls (please check):
- Artist songs preview shows 5 rows; "See All" only beyond that.
- An artist's albums are those where the artist is the album artist (not every album containing one of their tracks).
- Search is global from every tab even though the placeholder names the tab (the mockup's index page says "Search opens from the field in any tab" and screen 10 shows mixed results).
- Recently Added ascending = newest first.
- Track rows in album detail show the track artist only when it differs from the album artist.
- Artist avatars come from album covers.
- `#` entries sort after Z in every Songs sort (changes the v0.2.0 order, where titles starting with a digit came first).
- Album sort breaks ties between same-named albums by album artist, so their tracks never mix.
- Index taps on an empty letter go to the next letter in the alphabet that has a section.
